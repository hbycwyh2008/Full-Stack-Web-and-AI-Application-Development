# Lesson 29 — Figma Prototype and Design Gate

## Mission
Reach a testable design baseline before substantial implementation begins.

## Core Artifact
Capstone user flow + wireframes + high-fidelity Figma prototype + design review record.

## Launch Challenge — 0–10
Teams identify which requirement is hardest to express clearly in an interface and explain why.

## Evidence / Resource Scan — 10–25
Use research, requirements, and the Figma unit as evidence. No new feature may enter the design without a requirement or documented hypothesis.

## Team Sensemaking — 25–40
Walk through the primary user flow and error/recovery paths. Check information architecture and accessibility constraints.

## Studio Build — 40–65
Complete the Figma baseline with reusable components and responsive intent.

## Critique / Test — 65–80
Run a peer task walkthrough/design critique. Reviewers check requirement coverage, hierarchy, states, accessibility, and unnecessary complexity.

## Ship Evidence — 80–90
Resolve high-impact design issues and record the design gate decision: **ready / ready with known issues / not ready**.

## Success Evidence
Implementation begins from a documented, critiqued design rather than from improvising screens in code.
