# Lesson 08 — Brainstorm Alternatives (Flow + Ideas)

**Length:** 45 minutes
**Loop step:** Brainstorm Alternatives
**OMSCS source:** CS6750 **3.4** Design Alternatives
**Principle lens:** **2.6 Mental models and representations** — designs should match how users think about the task
**Mission:** Turn needfinding evidence into several directions and a simple user flow — without polishing UI yet.
**EdStem:** [course 31962 lessons](https://edstem.org/us/courses/31962/lessons) → Lesson **3.4**
**Durable Evidence:** brainstorm board (8+ ideas) + one primary user flow sketch

## 0–5 min — Skill Warm-up

Watch the clip. Write:

1. Why multiple alternatives matter.
2. One way a user’s **mental model** might differ from a designer’s sketch.

Quickly list one evidence-backed need and one guess from your team packet.

## 5–9 min — Talk Robin 1

Pairs share evidence-backed needs vs feature guesses. Pick **one** user goal for today’s brainstorm. Name how the user currently thinks that goal works (mental model guess → to be tested later).

## 9–14 min — Entry Check

Write **four different** ways a student might reach that goal (not four colors of the same screen). Star the wildest and the safest idea.

## 14–19 min — Core Pattern

**Method:** Brainstorm first, polish later. Quantity before beauty.

**Lens:** Alternatives should explore different representations of the same task (list vs calendar vs chat, etc.), not only different skins.

Timed brainstorm:

1. Silent sticky notes — 3 minutes
2. Share and cluster — 2 minutes

Display **8+ ideas** and one cluster labeled “backed by our needfinding.”

## 19–30 min — Guided Practice

Choose **3 promising directions**. For the top direction, sketch a **primary user flow**: start · 3–5 steps · success · one stuck point. Gray-box only. Link steps to HCI evidence when possible.

## 30–40 min — Independent Rebuild

Add one alternative path or recovery step the group missed. Explain how it better matches a user’s mental model or need.

## 40–45 min — Talk Robin 2 + Evidence

Submit brainstorm board + flow. State which **3 directions** become low-fi prototypes in Lesson 09.

## Success Evidence

Students generate multiple alternatives from evidence, consider mental-model fit, and produce a simple user flow before styling.
