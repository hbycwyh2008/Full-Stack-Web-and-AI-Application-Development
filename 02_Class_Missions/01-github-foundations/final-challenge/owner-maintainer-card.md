# GitHub Team Launch — Owner / Maintainer Card

## Your Role

You are responsible for both a feature and the team's integration workflow.

### Your feature

```text
feature-html
```

Build the semantic HTML structure for the team's site.

### Your maintainer responsibilities

- Create `team-web-launch` on GitHub.
- Invite both collaborators.
- Create or help organize the three Issues and Project board.
- Work only on `feature-html`, not directly on `main`.
- Open a Pull Request for your own HTML feature.
- Review both collaborator Pull Requests.
- Inspect **Files changed** before merging.
- Request changes when needed.
- Approve and merge collaborator PRs when ready.
- Self-check the HTML PR before merging it.
- Verify the final `main` branch.
- Publish the finished project with GitHub Pages.

## Your Workflow

```text
Create repo
→ invite collaborators
→ plan Issues
→ clone
→ feature-html
→ edit
→ add
→ commit
→ push
→ open PR

Then switch hats:

review collaborator PRs
→ request changes / approve
→ merge
→ verify main
→ deploy GitHub Pages
```

## Review Standard

Do not merge because a button is green. Before each merge, check:

- Does the PR target `main`?
- Does the PR contain only the intended feature?
- Is the description meaningful?
- Does the feature work?
- Are there obvious broken links, missing files, or inconsistent names?
- Has requested feedback been addressed?

## Important

The Owner does **not** bypass the PR workflow for their own feature. Your HTML work still enters `main` through a Pull Request.
