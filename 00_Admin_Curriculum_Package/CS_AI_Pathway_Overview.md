---

## 1. Vision

The **Computer Science and AI Pathway** prepares students to understand, build, document, and present real software — including AI-powered web applications — with integrity and mastery.

This pathway is **not** a collection of isolated coding activities. It is a **vertically aligned learning pathway** that connects:

- computational thinking
- programming and software engineering
- robotics and applied CS (where offered)
- AI literacy and responsible AI use
- web development (HTML, CSS, JavaScript, React, Next.js)
- backend development (FastAPI, databases, APIs)
- GitHub portfolio and professional workflow
- project-based assessment and public presentation
- alignment with **AP Computer Science Principles (AP CSP)** and **AP Computer Science A (AP CSA)** where appropriate

Students move from **organizing and documenting learning** to **building and explaining real projects** they can show to teachers, parents, and future schools.

---

## 2. Why a CS & AI Pathway Is Needed

Students today encounter AI tools daily. A modern CS pathway must help them:

1. **Understand** how software and AI systems work — not just use them as black boxes.
2. **Build** real applications with evidence on GitHub and in portfolios.
3. **Use AI responsibly** — as a learning partner, not a shortcut.
4. **Connect** math, design, programming, and project work into one coherent story.
5. **Prepare** for AP CS courses, competitions, robotics, and future STEM pathways.

Without vertical alignment, schools risk offering disconnected “coding activities” that do not build durable skills or portfolio evidence.

## 6. Student Evidence

Students demonstrate learning through **multiple evidence types**, not a single exam:

| Evidence Type | Description |
|---|---|
| **GitHub repository** | Code, commits, branches, README, project folders |
| **Reflections** | What was learned, what was hard, how AI was used |
| **Rebuild / independent practice** | Proof they can recreate patterns without copying |
| **Oral explanation** | Describe code, debug steps, and design choices |
| **Portfolio / Notion** | Public-facing project showcase |
| **Presentations** | Demo day, capstone showcase |

See [Student_Evidence_Framework.md](Student_Evidence_Framework.md) for the full model.

## 9. Assessment Philosophy

Assessment is **mastery-based** and **evidence-based**:

- Running code once is not enough — students must **explain, rebuild, debug, modify, and apply**.
- AI tools are allowed when they **support learning**, not replace thinking.
- Teachers use rubrics for projects, GitHub portfolios, reflections, and presentations.
- Oral checks verify **student understanding**, not tool output alone.

See [Assessment_and_Mastery_Model.md](Assessment_and_Mastery_Model.md).
