# Interactive Progress Checker

The starter pack includes:

```text
.github/workflows/team-launch-progress.yml
```

When the starter files are copied into the root of the team's repository, GitHub automatically maintains an Issue named:

```text
🚀 GitHub Team Launch Progress
```

The Issue updates as the team works and checks for evidence of:

- three feature Issues;
- the three feature branches;
- HTML, CSS, and JavaScript Pull Requests targeting `main`;
- Owner review evidence on collaborator Pull Requests;
- merged feature Pull Requests;
- closed feature Issues;
- GitHub Pages configuration.

It also displays the team's **next mission**.

Some checkpoints remain intentionally manual because GitHub cannot reliably prove them from repository metadata alone:

- collaborator invitations were accepted;
- Issue assignments are correct;
- the Project board is organized correctly;
- local repositories were synchronized with `git pull`;
- commit messages and code quality meet the class standard;
- the deployed site behaves correctly;
- individual reflections are complete.

Students do not need to study GitHub Actions. The workflow is infrastructure for the exercise, similar to the automated feedback used by GitHub Skills.
