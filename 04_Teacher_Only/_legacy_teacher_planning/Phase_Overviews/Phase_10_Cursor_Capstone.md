# Phase 10: Cursor Capstone

**Your goal:** Use **Cursor** responsibly **after** you understand Git, literacy, design, TypeScript, Next.js, FastAPI, and integration.

> Cursor accelerates development — **you** remain responsible for understanding, testing, debugging, and presenting.

---

## What You Will Learn

- Planning before prompting
- Reading and testing AI-suggested code
- Debugging AI mistakes
- Documenting AI usage honestly

---

## Why This Matters

Professional developers use AI assistants — but **mastery** means you catch errors, revise code, and explain decisions. This phase practices that discipline before the final showcase.

## In-Class Learning Flow

### 1. Skill Warm-up
Write a **plan bullet list** for one feature before opening Cursor.

### 2. Talk Robin Round 1
- **You:** “I will ask Cursor to help with ___ but I will verify ___.”
- **Partner:** “AI must not replace ___ in my workflow.”

### 3. Entry Check
Name one thing you must do after AI generates code.

### 4. Core Pattern
```text
plan → small prompt → read diff → test → fix → commit → reflect on AI use
```

### 5. Guided Practice
Implement one scoped feature with Cursor; teacher reviews diffs.

### 6. Independent Rebuild
- [ ] Feature works and is **explained in README**
- [ ] Commits show **your** revisions, not one AI dump
- [ ] [cursor-reflection.md](../../03_Templates/cursor-reflection-template.md) complete
- [ ] AI usage note per policy

### 7. Talk Robin Round 2 + Evidence
Submit reflection + commit history screenshot.

---

## Required Evidence

- Program code with meaningful commit history
- **AI usage note** (required) — what AI did vs what you did
- Reflection: what Cursor got wrong and how you caught it
- Oral explanation of one AI-assisted change

---

## Extension Task
Refactor one module without Cursor to prove you can rebuild.

---

## Reflection Questions
1. What did Cursor get wrong?
2. What did you change after AI output?
3. What would you still build without AI?
