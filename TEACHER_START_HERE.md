# Teacher Start Here — Software Design, Development & AI

## Canonical Curriculum

Use [02_Class_Missions/README.md](02_Class_Missions/README.md). It retains **33 lesson identifiers**, with additional meetings for practice and assessment. Start with the [current teaching plan](00_Course_Overview/Current_Teaching_Plan.md) for the ordinary-class implementation.

## Priority Order

1. introduce computer science as a broad discipline, not coding alone;
2. complete software-development lifecycle;
3. GitHub development workflow;
4. HCI research end to end;
5. Figma design/prototyping end to end;
6. HTML/CSS/JavaScript implementation and computational thinking;
7. AI literacy through Melanie Mitchell;
8. Python/AI application extensions only if time remains.

## Lesson 00

The opening lesson has two required cores:

1. define computer science and distinguish it from programming;
2. apply computational thinking — decomposition, pattern recognition,
   abstraction, algorithm design, and test/refine — to a non-code problem.

The AP CSP relationship is documented separately and is not repeated in this
lesson.

## Classroom Flow

Use activity structures appropriate to the content. Students should inspect/create evidence, discuss, build, critique/test, revise, and preserve evidence. Avoid leading the whole lesson through serial teacher questions.

## AI Literacy

Use the [six-theme foundation path](02_Class_Missions/06-ai-literacy/foundation-path.md) in the L21–L24 block, initially six 45-minute meetings. Read selected passages in class; no regular pre-class reading homework. The existing twelve-meeting reading route is optional. Practice responsible AI use throughout development without forcing every reading into a product-design implication.

## Assessment Lens

Assess the chain of evidence:

**research → requirement → design → issue/branch/PR → implementation → test → revision → release → retrospective**.

A technologically simple project with a strong evidence chain is stronger than a framework-heavy project with weak HCI/testing/process evidence.
