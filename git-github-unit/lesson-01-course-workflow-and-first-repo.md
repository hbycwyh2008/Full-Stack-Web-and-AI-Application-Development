# Lesson 1: Course Workflow and First GitHub Repository

**Duration:** 80 minutes  
**Target mastery after lesson:** Level 1–2 (Exposure → Copy/Run → begin Explain While Looking)

---

## 1. Lesson Goal

Students understand **how this course works** (mastery model, evidence, expectations) and complete their **first GitHub workflow**: create `cs-learning-log`, write `README.md`, commit, and submit Exit Evidence.

## 3. Core Vocabulary

| Term | Student-friendly definition |
|---|---|
| **Repository (repo)** | A project folder on GitHub that stores your files and history |
| **README.md** | The homepage file people see when they open your repo |
| **Commit** | A saved snapshot of your work with a short message describing what changed |
| **Commit history** | The list of all commits — proof of how your work changed over time |
| **Evidence** | Proof of learning: commits, screenshots, logs, oral explanation |
| **Mastery level** | How independently you can rebuild a skill (0–5) |
| **Independent Rebuild** | You do the task with a checklist, not by copying the full solution |

---

## 4. Core Pattern

```text
create repository → edit README → commit changes → check commit history → submit evidence
```

## 6. Skill Warm-up (0–20 min)

**Task:** Watch **one** selected clip (5–8 min) from GitHub for Beginners or the brief Git intro video.

**While watching, note:**

- One reason people use GitHub
- One thing that is **not** enough to count as “learning” in this course

**Teacher distributes:** `mastery-levels.md` and `unit-summary-one-page.md`.

**Do not** assign full playlist completion.

---

## 7. Entry Check (20–30 min)

Individual — no talking.

1. What is one thing you will **build or document** in this course? (not only watch)
2. What is the difference between **watching a tutorial** and **mastery Level 3**?
3. Name **two types of evidence** this course accepts besides “the teacher saw me type.”
4. What is one thing AI tools **should not** do for you in this course?
5. Have you used GitHub before? Yes / No / A little — one sentence.

---

## 8. Talk Robin Round 1 (30–34 min)

**Prompts:**

- A: “This course is different from a lecture class because…”
- B: “The mastery level I want to reach this unit is Level ___ because…”
- **Shared:** One question we still have for the teacher.

Follow `talk-robin-rules.md` timing.

## 9. Teacher Pattern Explanation (34–45 min)

### A. Course learning model (required — not only GitHub)

Explain clearly:

- This is a **classroom-based mastery** course.
- Students learn by **building, rebuilding, debugging, explaining, and submitting evidence**.
- The course is **not** only following the teacher or copying code.
- **Mastery levels 0–5** track independence (see handout).
- **Most core learning happens in class.** Homework is light if classroom evidence is finished.
- **Evidence:** GitHub commits, Notion, screenshots, learning logs, oral explanation.
- Principles: watching ≠ mastery; copying ≠ mastery; debugging is learning; AI supports but does not replace thinking.

### B. GitHub pattern today

1. Create repo `cs-learning-log` (public unless school policy differs)
2. Add `README.md` with required sections (below)
3. **Commit** with a message that describes what you added
4. Open **Commits** tab — history is learning evidence
5. Submit link + screenshot

**README required content:**

```markdown
# CS Learning Log

This repository records my learning progress in this course.

## What I will learn

- Git and GitHub
- Notion portfolio
- HTML and CSS
- JavaScript
- React
- Next.js
- FastAPI
- AI application projects

## How I will learn

- I will practice instead of only watching.
- I will debug step by step.
- I will write meaningful commits.
- I will explain my work clearly.
- I will use AI tools responsibly.
```

Demo on screen: create repo → edit README → commit → show history.

---

## 10. Guided Practice (45–60 min)

**Together with teacher:**

1. Students create `cs-learning-log` on GitHub.
2. Add README using template; personalize **one** bullet under “What I will learn” or “How I will learn.”
3. Commit message example: `Add initial README with learning goals`
4. Everyone opens **Commits** — verify message appears.
5. Reference GitHub Docs Hello World if students need steps.

Teacher circulates for account/auth issues.

---

## 11. Independent Rebuild (60–72 min)

**Checklist (Level 3 preview):**

- [ ] Repo name is `cs-learning-log`
- [ ] README has all required headings and bullets
- [ ] At least **one personal sentence** added (your name, goal, or interest)
- [ ] Commit message is **meaningful** (not `update`)
- [ ] Commits tab shows your commit
- [ ] Prepared Exit Evidence sentences

**No copying** another student’s personal sentence. No AI paste without revision and understanding.

---

## 12. Talk Robin Round 2 (72–76 min)

**Prompts:**

- A: “The core pattern today in one sentence is…”
- B: “My commit message says ___ because ___.”
- **Shared:** What Exit Evidence will we submit in the next 4 minutes?

---

## 13. Exit Evidence (76–80 min)

Submit to teacher (form/LMS/class folder):

1. **GitHub repository link**
2. **README screenshot**
3. One sentence: **What is a commit?**
4. One sentence: **How is this course different from a normal lecture class?**

## 15. Common Mistakes

- Creating repo under wrong name
- Confusing teacher course repo with personal repo
- “Saving” on GitHub editor but forgetting **Commit changes**
- Empty README or only title
- Vague commit message: `first`, `readme`, `update`

See `teacher-notes/common-student-mistakes.md`.
