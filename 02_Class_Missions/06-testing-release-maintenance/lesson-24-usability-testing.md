# Lesson 24 — Usability Test Plan and Sessions

## Mission
Observe whether real users can complete the intended task without turning the session into a tutorial.

## Core Artifact
`testing/usability-test.md` with protocol, observations, and findings.

## Launch Challenge — 0–10
Students watch/read a short test scenario and mark moments when a facilitator accidentally helps the participant.

## Evidence / Resource Scan — 10–25
Review product requirements and primary user flow. Convert success criteria into realistic tasks without telling participants exactly which controls to use.

## Team Sensemaking — 25–40
Teams define task, success/failure signal, what to observe, facilitator script, note-taking format, and consent/privacy boundaries.

## Studio Build — 40–65
Run usability sessions. Facilitator stays neutral; observers capture actions, hesitation, errors, quotes, completion, and recovery.

## Critique / Test — 65–80
Compare sessions. Separate **one person's preference** from repeated friction or a requirement failure. Rank findings by severity and confidence.

## Ship Evidence — 80–90
Create GitHub issues for actionable findings and commit the test summary.

## Success Evidence
Students can explain the difference between usability evidence and opinions about visual taste.
