# Class Missions — Software Design, Development & AI

This is the **canonical lesson pathway**.

## Before Lesson 00: Required Four-Poster Orientation

The course does **not** begin with a definition of computer science, AP CSP, GitHub, or coding.

Students first complete:

- [Required Orientation — Learn the Course Through the Four Posters](00-course-orientation/required-orientation-four-posters.md)

The four posters establish the rules students will use in every later lesson:

1. **Our Classroom Flow**
2. **Mastery Level**
3. **AI Use Policy**
4. **CS Competition Pathways**

Only after students understand those four posters does Lesson 00 define
**computer science**, distinguish it from programming, and use computational
thinking to solve and refine a non-code problem.

## Priority Order

### Primary outcomes
1. Understand and use the course learning culture defined by the four posters
2. Understand computer science and apply computational thinking to problems
3. Complete the software-development lifecycle
4. GitHub development and collaboration workflow
5. HCI user research
6. Figma product design
7. AI literacy through Melanie Mitchell

### Secondary outcomes
- HTML
- CSS
- JavaScript

### Optional
- Python
- small AI API/application extensions

## What Students Repeatedly Do

```text
understand → research → define → design → plan → build → review/test → release → learn → iterate
```

GitHub supports the workflow throughout the course.

## Canonical Classroom Method

Every class is **45 minutes** and uses **only** the seven blocks on the **Our Classroom Flow** poster:

1. **Skill Warm-up** — 0–5 min  
2. **Talk Robin 1** — 5–9 min  
3. **Entry Check** — 9–14 min  
4. **Core Pattern** — 14–19 min  
5. **Guided Practice** — 19–30 min  
6. **Independent Rebuild** — 30–40 min  
7. **Talk Robin 2 + Evidence** — 40–45 min  

See [shared/classroom-flow.md](shared/classroom-flow.md).

Do **not** invent alternate block names. Activity inside each block may change; the names stay fixed.

The teacher does **not** lead the class through a long sequence of questions. Students first meet the idea, talk, check understanding, practice, rebuild, and show evidence. Teacher explanation in **Core Pattern** is short.

## Final Product Standard

The capstone must demonstrate an evidence-backed user problem, HCI research, Figma design, GitHub history, HTML/CSS/JavaScript implementation, usability/accessibility/technical testing, deployment, and iteration.

AI implementation is optional. Students do **not** need to force a Mitchell reading connection into the product.
