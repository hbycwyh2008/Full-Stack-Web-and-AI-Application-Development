# Lesson 18 — Figma-to-Code Implementation Sprint

## Mission
Implement a complete primary page/flow from the design baseline and use comparison evidence to improve it.

## Core Artifact
A responsive HTML/CSS implementation of the selected Figma flow.

## Launch Challenge — 0–10
Each student identifies the three implementation risks most likely to cause design or usability drift.

## Evidence / Resource Scan — 10–25
Review Figma handoff notes, acceptance criteria, and open GitHub issues. Teams select scope for the sprint.

## Team Sensemaking — 25–40
Break the work into issues/branches and assign ownership while identifying shared components that should not be duplicated.

## Studio Build — 40–65
Implement. Use semantic structure, reusable CSS, responsive behavior, and accessibility states. Commit in coherent increments.

## Critique / Test — 65–80
Run side-by-side design comparison and a short task walkthrough. Classify gaps as **visual, behavior, content, accessibility, or requirement mismatch**.

## Ship Evidence — 80–90
Fix one high-impact gap, open issues for the rest, and submit the PR for review.

## Success Evidence
Students treat implementation as translating and validating design intent, not merely making a page look similar.
