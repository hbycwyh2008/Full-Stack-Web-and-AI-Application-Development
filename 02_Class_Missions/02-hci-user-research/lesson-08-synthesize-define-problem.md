# Lesson 08 — Synthesize Findings and Define the Problem

## Mission
Move from scattered user evidence to a defensible problem definition.

## Core Artifact
Affinity map + user profile/persona + journey/task map + problem statement.

## Launch Challenge — 0–10
Individually group anonymized research snippets by similarity without naming the groups first.

## Evidence / Resource Scan — 10–25
Review all team research notes. Each student selects five high-signal pieces of evidence and explains why they matter.

## Team Sensemaking — 25–40
Build an affinity map. Name clusters only after evidence is grouped. Mark contradictions and minority experiences rather than deleting them.

## Studio Build — 40–65
Create:

- evidence-backed user profile/persona;
- current journey or task flow;
- top needs/pain points;
- problem statement: **[user] needs a way to [need] because [evidence/context]**;
- 3–5 product requirements and measurable success criteria.

## Critique / Test — 65–80
Another team runs an “evidence audit”: every requirement must trace back to research. Remove decorative or assumption-only requirements.

## Ship Evidence — 80–90
Commit the synthesis summary and open design issues for the next unit.

## Success Evidence
Students can trace a requirement backward to user evidence and forward to a testable success criterion.
