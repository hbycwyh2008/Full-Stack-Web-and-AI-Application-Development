# Lesson 01 — Product Teardown: Trace the Lifecycle

## Mission
Reverse-engineer the development decisions behind an existing website or app without seeing its source code.

## Core Artifact
`research/product-teardown.md`

## Launch Challenge — 0–10
Choose one familiar product. Individually capture three interface decisions and infer the user problem each decision is trying to solve.

## Evidence / Resource Scan — 10–25
Use the live product or screenshots as the only required evidence. Mark examples of navigation, feedback, error prevention, accessibility, and user data collection.

## Team Sensemaking — 25–40
Teams compare products and classify observations under **research / requirements / design / implementation / testing / maintenance**. Record one observation that could fit more than one stage.

## Studio Build — 40–65
Create a teardown with:

- target users;
- likely user goal;
- three inferred requirements;
- two design choices;
- one possible implementation challenge;
- two tests the team would run;
- one improvement hypothesis.

## Critique / Test — 65–80
Another team challenges one inference: “What evidence supports that?” Revise any claim that is only an assumption.

## Ship Evidence — 80–90
Commit the teardown and add a short reflection: **Which lifecycle stage most changed how you look at software?**

## Success Evidence
The student distinguishes observations, assumptions, requirements, design decisions, and tests.
