# Role Card — Owner / Maintainer

## Your Feature

```text
Branch: feature-html
Issue: Build HTML structure
Primary file: index.html
```

## Your Integration Responsibility

You are the Maintainer for the shared repository.

You must:

1. create `team-web-launch`;
2. invite both collaborators;
3. copy the complete starter pack, including `.github/workflows/team-launch-progress.yml`;
4. create/assign the HTML Issue and help the team set up the three feature Issues;
5. create the team Project and complete the automatically created **📋 Project Evidence** Issue;
6. clone the repository and do your HTML work locally on `feature-html`;
7. make a meaningful local Git commit and push the branch;
8. open `feature-html → main` as a Pull Request using the real HTML Issue number in `Closes #...`;
9. review both collaborator PRs substantively;
10. submit **Changes Requested** on at least one collaborator PR and wait for that collaborator's follow-up commit;
11. approve/merge collaborator work when ready;
12. self-check and merge your own HTML PR;
13. complete **🔄 Local Sync Check** after all merges;
14. publish the final `main` with GitHub Pages;
15. complete **🧠 Final Reflection**.

## Integration Rule

Collaborators do not decide when work enters `main`.

```text
Collaborator PR
      ↓
Owner review
      ↓
request changes / approve
      ↓
Owner merge
      ↓
main
```

## Review Quality

A review must say something specific about the proposed change. A reaction such as `LGTM` alone is not sufficient for the challenge checker.

At least one collaborator PR must follow:

```text
Changes Requested
→ collaborator edits locally
→ collaborator commits + pushes
→ same PR updates
→ re-review
```

## Do Not

- develop directly on `main`;
- edit CSS or JavaScript as your feature work;
- complete your HTML feature only with GitHub's web editor;
- merge collaborator PRs before meaningful review;
- assume the feature Issue numbers are #1/#2/#3.

Use **🚀 GitHub Team Launch Progress** as your team's Mission Control page.
