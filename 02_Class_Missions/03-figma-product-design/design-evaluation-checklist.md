# Design + Evaluation Checklist — Core 3

Use this card in Lessons 09–11.

## A. Course Core 3

| Principle | Ask | Evidence to look for |
|---|---|---|
| **Affordance / signifier** | Can the user tell what can be clicked, typed, dragged, or changed? | User notices the primary action without coaching |
| **Mapping** | Can the user predict what will happen after the action? | Labels, icons, layout, and results match the expected outcome |
| **Constraints** | Does the interface prevent or reduce invalid actions? | Disabled states, input limits, confirmations, clear valid choices |

These are the **course Core 3**, not the complete CS6750 principle set.

## B. Quick designer review

Before user testing, mark each:

- [ ] Main action is obvious.
- [ ] Labels describe the result, not only the control.
- [ ] Similar actions behave consistently.
- [ ] Invalid / dangerous actions are prevented or recoverable.
- [ ] Text is readable and important information does not depend only on color.

Write the biggest predicted problem:

> We think the user may get stuck at __________________ because __________________.

Priority:

- **MUST** — blocks the main task
- **SHOULD** — creates confusion / unnecessary effort
- **LATER** — polish / optional feature

## E. Retest

Use the **same core task** after the revision.

> First test: __________________  
> Change: __________________  
> Second test: __________________

A better-looking screen is not enough. The design improved when the user can complete the task more clearly, accurately, or independently.
