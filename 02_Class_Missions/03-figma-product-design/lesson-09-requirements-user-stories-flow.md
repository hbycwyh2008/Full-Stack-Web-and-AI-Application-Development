# Lesson 09 — Requirements, User Stories, and User Flow

## Mission
Translate research findings into a small set of user stories and a flow that can later be designed, coded, and tested.

## Core Artifact
`design/requirements-and-user-flow.md` plus a Figma/FigJam flow.

## Launch Challenge — 0–10
Given mixed statements, sort them into **user need / functional requirement / design idea / success criterion**.

## Evidence / Resource Scan — 10–25
Return to research evidence. Highlight which findings justify each proposed requirement.

## Team Sensemaking — 25–40
Teams prioritize requirements using **must / should / could / not now**. Every “must” needs an evidence link.

## Studio Build — 40–65
Write 3–5 user stories in the form **As a [user], I want to [goal], so that [reason]**, add acceptance criteria, then draw the primary user flow including start, decisions, success, and error/recovery paths.

## Critique / Test — 65–80
A peer team walks through the flow as a user and marks dead ends, missing states, and unnecessary steps.

## Ship Evidence — 80–90
Revise the flow and commit requirements with a link to the Figma/FigJam artifact.

## Success Evidence
The flow can be traced back to research and forward to concrete acceptance criteria.
