# Phase 3: Cursor Quick Win

## Phase Goal
Get a fast, visible AI-assisted result to build confidence with Cursor — while practicing responsible AI use.

## Key Concepts
- How to ask Cursor for help and read AI-generated code.
- How to make at least one manual change and test what AI produced.
- How to write an honest AI usage reflection.

> AI can help generate code, but the student is responsible for understanding, testing, debugging, and presenting the project.

## Required Student Output
- A very small AI-assisted web page or mini app.
- At least one manual change you made to the generated code.
- A short AI usage reflection.

---

## Suggested Lesson Count
2 lessons.

## Lesson Sequence

### Lesson 1: First AI-Assisted Build
- **Goal:** Install Cursor and generate a working mini page.
- **Warm-up:** "What would you build if coding were fast and easy?"
- **Mini Lesson:** Review the **AI Usage Policy**. Tour Cursor; show how to write a clear prompt and read the result. (Optional: Cursor video resources.)
- **Guided Practice:** Whole class builds the same small page with Cursor (e.g., a profile card or simple counter).
- **Independent Work:** Each student customizes the page (colors, text, one feature).
- **Exit Ticket:** What did Cursor generate, and what did you change?
- **Homework:** Finish the mini app so it runs.

### Lesson 2: Understand, Test, and Reflect
- **Goal:** Prove understanding of the generated code and reflect on AI use.
- **Warm-up:** "Explain this line" — show a line of generated code and ask what it does.
- **Mini Lesson:** Why "I accepted it" is not the same as "I understand it." Connect to the AI Usage Policy and Phase 0.
- **Guided Practice:** Students test their app and annotate three lines of code with comments in their own words.
- **Independent Work:** Write an AI usage reflection using `01_Student_Templates/AI_Usage_Reflection_Template.md`.
- **Exit Ticket:** Name one thing you accepted from AI that you did NOT fully understand.
- **Homework:** Push the mini app to GitHub with a short README.

## Submission Requirements
- [ ] Working mini app.
- [ ] One documented manual change.
- [ ] Code annotated with student explanations.
- [ ] AI usage reflection completed.

## Common Student Problems
- Accepting code blindly without reading it → require the "explain 3 lines" annotation.
- Over-ambitious projects that break → keep the first build small.
- Not testing before submitting → require the app to actually run.
- Forgetting to disclose AI usage → reinforce the AI Usage Policy.

## Teacher Notes
> 重点是建立信心，同时坚持"必须理解代码"的规则。The focus is confidence, but hold the rule: students must read, test, and understand what they submit. Optional Cursor videos help, but remind students our main backend is FastAPI, not Next.js Server Actions.

## AI Lens Reflection
Ask students: *"This is your first time letting AI write code for you. What rule will you set for yourself about checking AI's work?"* Save the answer in Learning Notes.
