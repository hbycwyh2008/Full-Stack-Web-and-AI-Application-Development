# Mastery Levels — Git & GitHub Unit

Use these levels to understand **your** progress. The goal is not “finished the video.” The goal is **what you can do without copying**.

![Mastery Level poster](../../../08_Public_Documents/posters/mastery-level.png)

*Course poster: [mastery-level.png](../../../08_Public_Documents/posters/mastery-level.png)*

---

## Level 0: Exposure

You have **seen** the idea through a short video, reading, example, or teacher demo.

**Example:** You watched a GitHub Hello World clip. You cannot create a repo alone yet.

**Not enough for course credit** by itself.

---

## Level 1: Copy and Run

You can **follow instructions**, copy the example, and make it work.

**Example:** Teacher shows create repo → you repeat steps and your README appears.

**Still fragile** — you may not know why each step matters.

---

## Level 2: Explain While Looking

You can **look** at the code, command, or project and explain what the important parts do.

**Example:** You open your Commits tab and explain what one commit changed and why the message matters.

---

## Level 3: Rebuild with Checklist

You can **recreate the same pattern** using a short checklist — **without copying the full solution**.

**Example:** Checklist says “create file → write heading → commit with message describing change” — you do it from memory of the pattern, not paste.

**Minimum target** for end of this unit.

---

## Level 4: Rebuild Without Notes

You can recreate the pattern from a **blank file, blank page, or terminal** without notes, tutorials, AI answers, or solution code.

**Example:** Teacher says “add a new lesson folder and notes file” — you do it cold.

---

## Level 5: Modify, Debug, and Transfer

You can use the same pattern in a **new situation**, **modify** it, **debug** common errors, and **help another student** locate a problem (without giving them your full solution).

**Example:** You fix a broken Markdown link in README, write a better commit message, and help a peer find why their commit did not appear on GitHub.

---

## Course Expectation Principles

- **Watching is not mastery.**
- **Copying is not mastery.**
- **Running code once is not mastery.**
- **Understanding code is not the same as being able to write or rebuild it.**
- **Debugging is part of learning, not failure.**
- **AI tools can support learning, but they cannot replace thinking.**
- You may be asked to **explain your work orally**.
- You must submit **evidence** through GitHub commits, screenshots, learning logs, Notion updates, or short reflections.
