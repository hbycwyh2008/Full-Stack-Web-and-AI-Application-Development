# Student Learning Expectations

This course is **not** a typing-along exercise. Students are expected to develop real engineering habits: reading code, debugging problems, asking thoughtful questions, and reflecting on what they learn.

> **Core expectation:** You may use AI and follow guided steps, but you must be able to explain what the code does, find and fix problems yourself, and show evidence of your own thinking.

---

## What Success Looks Like

A strong student in this course:

- **Reads code before running it** — understands file structure, function names, and data flow.
- **Debugs independently first** — reads error messages, checks logs, forms a hypothesis, then tries a fix.
- **Asks specific questions** — not "it doesn't work," but "this API returns 404 when I call `/ask`; I think the route path is wrong because..."
- **Reflects regularly** — records what worked, what failed, what confused them, and what they learned.
- **Tests their own work** — does not assume copied or AI-generated code is correct until verified.

---

## Required Habits (Every Phase)

### 1. Read Code, Don't Just Type It

Before adding new code, students should:

- Identify which file they are editing and why it belongs there.
- Trace how data moves (input → processing → output).
- Explain in their own words what each major function or component does.
- Mark or note lines they do not understand — and follow up until they do.

**Minimum evidence:** weekly learning journal entry, README explanation, or portfolio notes showing code comprehension.

### 2. Debug Before Asking for Help

When something breaks, students should follow this order:

1. Read the full error message (line number, file, stack trace).
2. Reproduce the problem consistently.
3. Change one thing at a time and observe the result.
4. Search documentation or prior lessons for similar issues.
5. Write down what they tried — even if it did not work.

**Only after these steps** should they ask the teacher, a peer, or AI for help — and their question should include what they already tried.

### 3. Think, Question, and Reflect

Students should:

- Predict what will happen before they run code.
- Compare expected vs. actual behavior when results differ.
- Ask "why" and "what if" — not only "how do I finish this step."
- Complete weekly reflections using `01_Student_Templates/Learning_Journal_Template.md`.
- Disclose AI usage honestly using `01_Student_Templates/AI_Usage_Reflection_Template.md`.

---

## What Is Not Acceptable

- Running or copying code without reading it.
- Asking AI or the teacher to fix errors without attempting debugging first.
- Submitting projects that work but cannot be explained.
- Treating Cursor or other AI tools as a substitute for understanding.
- Skipping reflection because "the project runs."

---

## How Teachers Can Reinforce This

- Start lessons with a **code reading** warm-up (explain this function, predict this output).
- Require a **debug log** or "what I tried" note for significant bugs.
- Grade explanations and process — not only whether the app runs.
- Use `02_Assessment/Assessment_Rubric.md` questions on comprehension and debugging during check-ins and final presentation.

---

## Student Commitment

By participating in this course, students commit to:

```text
I will read and try to understand code — not only type it.
I will attempt to debug problems myself before asking for help.
I will ask specific, thoughtful questions based on what I have tried.
I will reflect on my learning regularly and honestly.
I will test my work and explain what I built in my own words.
```
