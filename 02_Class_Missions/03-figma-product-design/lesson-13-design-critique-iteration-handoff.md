# Lesson 13 — Design Critique, Iteration, and Handoff

## Mission
Use critique to improve the prototype and prepare design decisions for implementation.

## Core Artifact
Design review log + implementation handoff notes.

## Launch Challenge — 0–10
Sort feedback into **observation / interpretation / suggestion / preference**. Identify which feedback is actionable without more evidence.

## Evidence / Resource Scan — 10–25
Teams review their requirements, user flow, and latest prototype side by side. Mark where the design does not clearly satisfy a requirement.

## Team Sensemaking — 25–40
Run structured critique: designer states the goal and constraint; reviewers identify evidence-based strengths, risks, and questions; designer listens before responding.

## Studio Build — 40–65
Prioritize critique findings by user impact and effort. Revise the prototype. Create handoff notes containing component names, spacing/layout intent, content, states, responsive rules, and acceptance criteria.

## Critique / Test — 65–80
A developer-role peer attempts to describe how they would implement the design using only the handoff. Missing information becomes a design issue.

## Ship Evidence — 80–90
Freeze a “design baseline” version in Figma and commit handoff notes. Later code changes may trigger design iteration; the design is not treated as permanently finished.

## Success Evidence
Students can show how research became requirements, requirements became design, and design is now ready to be implemented and tested.
