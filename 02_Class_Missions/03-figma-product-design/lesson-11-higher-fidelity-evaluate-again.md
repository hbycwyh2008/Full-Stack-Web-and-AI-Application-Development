# Lesson 11 — Higher-Fidelity Prototype + Evaluate Again

**Length:** 45 minutes  
**Loop step:** Brainstorm Again → Higher-Fidelity Prototype → Evaluate Again  
**Mission:** Rebuild the improved direction as a clickable higher-fidelity prototype, then run a second short evaluation and record what changed.  
**One Required Resource / Evidence Source:** Lesson 10 revision list + low-fi frames  
**Durable Evidence:** clickable high-fi prototype + second-eval notes + before/after change log

## 0–5 min — Skill Warm-up

Review a teacher high-fi / Figma prototype example. Note hierarchy, contrast, clear labels, and clickable hotspots. Write one risk of polishing too early.

## 5–9 min — Talk Robin 1

Pairs turn the revision list into a **build checklist** (screens + states to finish today). Cut anything that is “nice” but not needed for the main task.

## 9–14 min — Entry Check

Individually inspect a pretty mock interface. Mark two places where polish does **not** prove the product is easy to use.

## 14–19 min — Core Pattern

Must-know: **Fidelity goes up after evidence.** High-fi should still serve the same user goal.

Quick second brainstorm (2 minutes): if Lesson 10 revealed a new need, add **one** small alternative idea — then choose whether to include it now or later.

Groups show the **before → after** change they must ship today.

## 19–30 min — Guided Practice

Build/revise the higher-fidelity Figma prototype:

- primary flow screens;
- clear labels and contrast;
- success + one error/empty state;
- clickable transitions for the main task;
- apply at least **two** Lesson 10 revisions.

Then **Evaluate Again** (3–5 min): a peer runs the same core task. Note success and one remaining issue.

## 30–40 min — Independent Rebuild

Individually complete a change log:

1. What we changed after the first evaluation.  
2. What the second evaluation showed.  
3. One open needfinding question for later (Test stage / capstone).

## 40–45 min — Talk Robin 2 + Evidence

Submit Figma link, second-eval notes, and change log. State how this prototype is ready (or not) for Build-stage HTML/CSS.

## Success Evidence

Students ship a clickable higher-fidelity prototype improved by two evaluation passes, and can explain what evidence drove the changes.
