# Lesson 25 — Bug Triage, Accessibility QA, and Iteration

## Mission
Prioritize problems using user impact and requirements instead of fixing whatever is easiest first.

## Core Artifact
Triaged issue board + QA checklist + revised release candidate.

## Launch Challenge — 0–10
Rank sample issues by severity: cosmetic spacing, keyboard trap, broken main task, unclear label, rare edge-case error. Students defend rankings using user impact.

## Evidence / Resource Scan — 10–25
Review usability findings, acceptance criteria, browser/viewport tests, keyboard behavior, labels/semantics, contrast, focus, and error feedback.

## Team Sensemaking — 25–40
Teams classify issues as **blocker / high / medium / low**, add reproduction steps and acceptance criteria, and identify which issues should be grouped into one fix.

## Studio Build — 40–65
Fix highest-priority issues on branches. Retest the original failure, then run regression checks on related behavior.

## Critique / Test — 65–80
Peer performs the exact issue reproduction steps and acceptance criteria. A fix is not accepted only because the author says it works.

## Ship Evidence — 80–90
Merge verified fixes and update the issue board with evidence.

## Success Evidence
Students can justify prioritization and show a test that proves the issue is resolved.
