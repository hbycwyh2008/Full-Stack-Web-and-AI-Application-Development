# Lesson 32 — Capstone: Release, Showcase, and Retrospective

**Mission:** Release the best supported version, let people use it, and reconstruct how evidence changed the product.

## Final QA + Release (0–20)

Run must-pass checks, merge approved fixes, deploy, and create release notes with known limitations.

## Product Showcase (20–50)

Prefer **use over presentation**. Visitors attempt the product's main task. Students provide context but do not give a long slide deck before users interact.

Collect concise feedback as additional evidence.

## Evidence Timeline (50–66)

Teams reconstruct at least three moments where evidence changed the project:

```text
original belief/design → evidence → decision/change → result
```

Possible evidence: research, prototype test, code review, usability test, QA defect.

## Retrospective (66–82)

Address:

- what process step prevented the biggest mistake?
- where did the team ignore or misread evidence?
- how did GitHub help or hinder collaboration?
- which implementation decision was hardest to debug?
- what would the next version test first?

## Individual Reflection (82–90)

Students independently explain how their definition of `building software` changed from Lesson 00 to Lesson 32.

## Final Standard

The final grade should reflect the **quality of the development evidence chain**, not only visual polish or technology count. AI is not required.
