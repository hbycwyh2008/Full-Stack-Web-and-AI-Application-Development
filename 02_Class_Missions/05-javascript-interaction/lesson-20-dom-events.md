# Lesson 20 — DOM and Events

## Mission
Connect user actions to visible interface changes while preserving clear HTML structure.

## Core Artifact
One working interaction using DOM selection, events, and explicit state changes.

## Launch Challenge — 0–10
Students trace an interaction diagram: **user action → event → handler → state/decision → DOM update** and identify which step is missing in a broken example.

## Evidence / Resource Scan — 10–25
Inspect a minimal DOM/event example. Annotate selector, event listener, handler, changed property/content, and feedback to the user.

## Team Sensemaking — 25–40
Teams compare possible event choices (`click`, `input`, `submit`, etc.) for product behaviors and justify which event matches the user action.

## Studio Build — 40–65
Implement one designed interaction such as tabs, menu, filter, disclosure, counter, theme choice, or task state. Use named functions when logic is non-trivial.

## Critique / Test — 65–80
Peer tests mouse, keyboard, repeated actions, and unexpected order of actions. Record reproducible failures.

## Ship Evidence — 80–90
Debug the highest-impact issue and commit with test notes.

## Success Evidence
Students can trace a user action through event handling to a DOM change.
