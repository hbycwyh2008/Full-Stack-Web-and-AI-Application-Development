# Lesson 1: Notion Portfolio Structure


| | |
|:---|:---|
| **Time** | 90 minutes |
| **Evidence** | student repo + phase folder |

> [!TIP]
> Mission card → **45–70 Mission Task** → **70–80 Rebuild/Exit** → submit evidence.

## Lesson Goal

Build the first version of your Notion portfolio homepage so it can clearly show who you are, what you are learning, and where your GitHub evidence lives.

By the end of this lesson, you should have a Notion page with real sections, not just empty headings.

---

## Why This Lesson Matters

In the GitHub lessons, your repository proved that you can create evidence, make commits, and explain your learning process.

Now your Notion portfolio becomes the public showcase. GitHub shows the work history. Notion tells the story.

---

## Class Flow

```text
individual learning → Talk Robin / group discussion → group answer → Entry Points Check → teacher explains only what students do not understand → mission task → exit check → submission of evidence
```

---

## 1. Individual Learning

Open the Notion portfolio tutorial:

[How to Build a FREE Website with Notion (Full Tutorial)](https://www.youtube.com/watch?v=w8NQU9k4afM)

Watch only this part today:

**00:00–24:36**

Focus on:

1. What a portfolio website is for
2. How the page is divided into sections
3. How a blank Notion page becomes a structured homepage
4. How the portfolio section can show learning projects

While watching, write short notes for these questions:

1. What sections does the video use?
2. Which sections make sense for a student learning portfolio?
3. Where should your GitHub link appear?
4. What should your first project or evidence section show?

Do not try to build everything while watching. First understand the structure.

---

## 2. Talk Robin / Group Discussion

In your group, each student answers:

1. “A Notion portfolio is different from my GitHub repo because...”
2. “The most important section on my homepage will be...”
3. “My GitHub evidence should appear in the portfolio because...”

Each person speaks once before anyone speaks twice.

---

## 3. Group Answer

As a group, write one shared answer:

> A strong student Notion portfolio must include...

Your answer should include at least three required sections.

---

## 4. Entry Points Check

The teacher checks:

1. Do you understand the difference between GitHub and Notion?
2. Do you know what sections your portfolio needs?
3. Do you know where your GitHub repo link will go?
4. Do you have access to Notion?

The teacher explains only the parts students do not understand yet.

---

## 5. Mission Task

Create a new Notion page for your portfolio.

Suggested title:

```text
[Your Name] — Full-Stack Web and AI Portfolio
```

Build these sections:

1. **Hero / Welcome**
   - Your name
   - One sentence about what you are learning
   - One sentence about your goal for this course

2. **About Me**
   - Your background
   - Why you are learning full-stack web and AI
   - What kind of projects you want to build

3. **Learning Projects**
   - Add a first project card or heading for Git & GitHub
   - Write 2–3 sentences about what you learned in the GitHub lessons

4. **GitHub Evidence**
   - Add your `[studentName]-Full-Stack-Web-and-AI-Application` repository link
   - Explain that GitHub shows commits, files, and learning evidence

5. **Skills**
   - Add at least five skills you have started learning
   - Example: GitHub, Git, Markdown, Notion, portfolio writing

6. **Reflections**
   - Add one reflection: “What I learned from building my first portfolio structure”

Do not publish yet unless the teacher says to. Today’s goal is structure and content.

---

## 6. Independent Rebuild / Exit Check

Without replaying the tutorial, check your page from top to bottom.

You should be able to:

1. Add or rename a section by yourself.
2. Move one section to a better position.
3. Explain why each section belongs in your portfolio.
4. Find and open your GitHub repo link from the Notion page.

If you cannot do these without the tutorial, keep practicing before moving on.

---

## 7. Submission of Evidence

Submit:

1. Screenshot of your Notion portfolio homepage structure
2. Screenshot or link showing your GitHub Evidence section
3. One sentence: “My Notion portfolio is useful because...”
4. One sentence: “My GitHub repo is still important because...”

---

## Success Criteria

You are successful if:

1. Your Notion page has a clear portfolio title.
2. Your page includes Hero, About Me, Learning Projects, GitHub Evidence, Skills, and Reflections.
3. Your GitHub repo link appears on the page.
4. Your sections contain real student writing, not empty placeholders.
5. You can explain the difference between GitHub evidence and Notion showcase.

---

## Common Problems

| Problem | Try first |
|---|---|
| My page looks empty | Add short real sentences under each heading. |
| I only copied the video sections | Rename sections so they fit this course. |
| I cannot find my GitHub repo link | Open GitHub, go to your course repo, and copy the browser URL. |
| I want to publish immediately | First finish the structure and check your links. Publishing comes next lesson. |

---

## Fast Track Option

If most students complete this lesson in about 45 minutes, continue directly into Lesson 2 during the same 90-minute block.

Use this only if students have:

1. Built all required sections.
2. Added their GitHub repo link.
3. Written real content in their own words.
4. Completed the independent rebuild without watching the tutorial again.

If more than one third of the class is still missing the page structure, do not start publishing. Use the remaining time for page organization, link checks, and oral explanation.
