# Computer Science and AI Pathway

**Chongqing Norin Bashu School for Children of Foreign Personnel**  
Designed by **Morgan Wang**

---

## 1. Vision

The **Computer Science and AI Pathway** prepares students to understand, build, document, and present real software — including AI-powered web applications — with integrity and mastery.

This pathway is **not** a collection of isolated coding activities. It is a **vertically aligned learning pathway** that connects computational thinking, programming, robotics, AI literacy, web development, GitHub portfolio work, AP Computer Science preparation, project-based assessment, and documented student evidence.

Students move from organizing and documenting their learning to building and explaining real projects they can share with teachers, parents, and future schools.

---

## 2. Why a CS & AI Pathway Is Needed

Students today encounter AI tools, digital platforms, and software-driven systems every day. A modern pathway must help them:

1. **Understand** how software and AI systems work — not only use them as black boxes.
2. **Build** real applications with evidence on GitHub and in portfolios.
3. **Use AI responsibly** — as a learning partner, not a shortcut.
4. **Connect** design, programming, math, and project work into one coherent story.
5. **Prepare** for AP Computer Science courses, robotics, competitions, and future STEM pathways.

Without vertical alignment, schools risk offering disconnected coding activities that do not build durable skills or credible portfolio evidence.

## 3. Pathway Map

```text
Workflow & Tools
    ↓
Git, GitHub, Portfolio
    ↓
Web Foundations (HTML, CSS, JavaScript)
    ↓
Front-end Engineering (React, Next.js)
    ↓
AI Literacy + Math Bridge
    ↓
Back-end Engineering (FastAPI, Database)
    ↓
Full-Stack Integration + RAG Concepts
    ↓
Cursor / Vibe Coding Capstone
    ↓
Final Portfolio & Presentation (AI School Assistant)
```

**Full-Stack Web and AI Application Development** is the capstone course within this pathway. It is portfolio-first, evidence-based, and mastery-focused.

## 4. Grade Band Progression

| Stage | Focus | Typical Evidence |
|---|---|---|
| **Middle grades (G6–G8)** | Computational thinking, digital citizenship, introductory tools, block and text coding foundations | Lab notebooks, simple projects, reflection |
| **Early high school (G9–G10)** | Git workflow, web basics, AI literacy, structured projects | GitHub repositories, README files, weekly reflections |

The pathway can be further refined as grade-level course titles and scheduling decisions are finalized at the school level.

## 6. Student Evidence

Students demonstrate learning through **multiple evidence types**, not a single exam:

| Evidence Type | Description |
|---|---|
| **GitHub repository** | Code, commits, branches, README files, project folders |
| **Reflections** | What was learned, what was hard, how AI was used |
| **Rebuild and independent practice** | Proof students can recreate core patterns without copying |
| **Oral explanation** | Students describe code, debug steps, and design choices |
| **Portfolio / Notion** | Public-facing project showcase |
| **Presentations** | Demo day and capstone showcase |

This evidence model supports both daily learning and long-term portfolio growth.

## 9. Assessment Philosophy

Assessment is **mastery-based** and **evidence-based**:

- Running code once is not enough — students must **explain, rebuild, debug, modify, and apply**.
- AI tools are allowed when they **support learning**, not replace thinking.
- Teachers evaluate projects, GitHub portfolios, reflections, and presentations.
- Oral checks verify **student understanding**, not tool output alone.

This approach values growth, documentation, and honest learning habits over single high-stakes tests.

---

## 10. Implementation Notes

1. **Curriculum design** — Full curriculum materials are maintained in a private master repository for teachers and curriculum designers.
2. **Student Hub** — Student-facing guides and policies are published in a separate repository students can access safely.
3. **GitHub Classroom** — Assignments are delivered through organization-owned template repositories; students work in their own copies.
4. **Class rhythm** — A typical 90-minute class follows: learn → practice → rebuild → share.
5. **School communication** — Admin-facing documents such as this overview support conversations with school leaders, parents, and curriculum reviewers.

The pathway is designed to protect curriculum quality while giving students clear, appropriate access to what they need for learning.
