# Lesson 21 — Arrays, Objects, and Rendering Data

## Mission
Represent repeated product content as data instead of duplicated hard-coded markup.

## Core Artifact
A data-driven UI section rendered from an array of objects.

## Launch Challenge — 0–10
Students compare three repeated cards and identify which information changes and which structure stays the same.

## Evidence / Resource Scan — 10–25
Inspect a small array of objects and a rendering function. Mark object properties, array iteration, generated elements/templates, and output location.

## Team Sensemaking — 25–40
Teams design a data shape for one project feature and test whether it can represent all current examples plus one unusual case.

## Studio Build — 40–65
Create the data structure and render it into the interface. Add one operation such as filter, sort, search, or status grouping if it supports the user requirement.

## Critique / Test — 65–80
Partner adds a new object with unusual/long/missing optional content and checks whether the interface and code survive.

## Ship Evidence — 80–90
Fix robustness issues and commit data model + renderer.

## Success Evidence
Students can explain why separating data from repeated presentation improves maintainability.
