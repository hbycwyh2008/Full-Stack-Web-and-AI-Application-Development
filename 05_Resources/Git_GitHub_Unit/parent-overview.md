# Parent Overview — Git & GitHub Unit

**Course:** Full-Stack Web and AI Application Development
**Unit:** Git & GitHub Beginner (Phase 0 foundation)

---

## What Students Are Learning

Students are learning to use **GitHub** as a **learning portfolio** — not just to store files, but to show **how they learn** over time.

The unit has **15 classes**. Each class uses one video from GitHub's official
beginner playlist and one related practice. The GitHub Actions video is excluded
because workflow automation belongs later in the course.

They will:

- Create a personal repository called `YourName-Full-Stack-Web-and-AI-Application-Development`
- Write README files and learning notes in Markdown
- Make **commits** — saved snapshots of their work with clear messages
- Review **commit history** as evidence of progress
- Use branches, pull requests, issues, projects, Pages, and Markdown
- Learn profile, account, and repository safety
- Connect local work in VS Code to GitHub when the class is ready

---

## How This Course Is Different

This is **not** a traditional lecture class where watching a video counts as learning.

Students must:

- **Practice** during class
- **Rebuild** skills without copying full solutions
- **Debug** errors step by step
- **Explain** their work in writing and sometimes **orally**
- Submit **evidence** through GitHub, screenshots, and short reflections

**Watching, copying, or using AI to finish tasks without understanding does not meet course expectations.**

---

## Homework Expectations

Homework is limited to the day’s **learning-log Exit Ticket**. If students
save it before class ends, there is no homework. Lessons 1–2 are saved locally;
the repository is created in Lesson 3 and the earlier notes are uploaded in
Lesson 4.

There is no video homework. Unfinished practice continues in the next class
instead of becoming take-home work.

---

## What You Might See at Home

- Student working on `github.com` in their own repository
- Student writing three short learning-log prompts in Markdown
- Student explaining a commit message to you — good sign

---

## AI Tools

Students may use AI for **hints and explanations**, but they must **understand, test, and revise** their work. Teachers may ask students to explain their repository orally, especially if AI was used.

---

## How to Support Your Student

- Ask: “What did you commit today?” not only “Did you finish?”
- Encourage them to read error messages before asking for help
- Do not ask them to share API keys or passwords — these must never go on GitHub
