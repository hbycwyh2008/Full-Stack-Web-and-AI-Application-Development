# Phase 2: GitHub + Markdown

## Phase Goal
Learn version control and professional documentation by creating your first GitHub repository with a complete README.

## Key Concepts
- Repositories, commits, and the basic Git workflow.
- Markdown syntax: headings, lists, links, images, code blocks.
- GitHub + Markdown create **evidence of real learning**.

## Required Student Output
- A GitHub account and a first public repository.
- A project `README.md` using `01_Student_Templates/Project_README_Template.md`.
- A GitHub profile README using `01_Student_Templates/GitHub_Profile_README_Template.md`.
- At least three meaningful commits.

---

## Suggested Lesson Count
2 lessons.

## Lesson Sequence

### Lesson 1: Markdown and Your First Repo
- **Goal:** Write Markdown and create a repo with a README.
- **Warm-up:** Show plain text vs. formatted Markdown. "Which is easier to read?"
- **Mini Lesson:** Markdown basics from the **Markdown Crash Course** — headings, lists, links, images, code blocks.
- **Guided Practice:** Create a GitHub account (if needed) and a repository; add a README using `Project_README_Template.md`.
- **Independent Work:** Fill in the Overview and Problem sections.
- **Exit Ticket:** Write a Markdown heading, a list, and a link from memory.
- **Homework:** Complete the project README; start **GitHub Skills: Introduction to GitHub**.

### Lesson 2: Git Workflow and Profile README
- **Goal:** Understand commits and create a GitHub profile README.
- **Warm-up:** "What could go wrong if you never saved versions of your work?"
- **Mini Lesson:** Repos, commits, push; live demo of create → commit → push. Show signing in with a personal access token.
- **Guided Practice:** Students make three commits with clear messages.
- **Independent Work:** Create the special profile repo and add `GitHub_Profile_README_Template.md`.
- **Exit Ticket:** Explain what a commit is in one sentence.
- **Homework:** Finish the GitHub Skills activity; publish the profile README.

## Submission Requirements
- [ ] Public repo created.
- [ ] Project README follows the template.
- [ ] Profile README published.
- [ ] At least three meaningful commits.

## Common Student Problems
- Authentication fails → prepare a personal access token guide in advance.
- Vague commit messages ("update") → require messages that say what changed.
- Profile repo named incorrectly → it must match the username exactly.
- Forgetting to push → "saved locally" is not "on GitHub."

## Teacher Notes
> 强调清晰的提交信息和文档习惯。Emphasize clear commit messages and documentation habits. Authentication is the most common blocker — budget extra time and have a token walkthrough ready. Remind students that GitHub is the technical evidence behind their Notion showcase.

## AI Lens Reflection
Ask students: *"When you later use AI to write code, how will your README and commits show what you understood versus what AI generated?"* Note the answer in Learning Notes.
