# Grade-Band Expectations

This course uses **one shared repository and one common learning pathway** for both Middle School and High School students.

Students work with the same major technologies, class missions, project themes, evidence system, and portfolio structure. The difference is the expected level of **independence, technical depth, debugging ability, and mastery**.

> **Same professional tools. Same learning pathway. Different levels of independence and mastery.**

---

## Middle School Track — Guided Full-Stack Development

### Core Goal

**Build · Modify · Explain**

Middle School students are expected to understand the major ideas behind full-stack and AI-powered applications while working with appropriate teacher guidance, starter code, checklists, and scaffolding.

By the end of the course, a Middle School student should be able to:

- use GitHub to maintain a project repository and basic commit history;
- create and modify HTML, CSS, and JavaScript projects;
- understand basic React components and modify an existing React or Next.js application;
- use basic Python syntax, functions, and data structures;
- understand what an API is and modify a provided FastAPI endpoint;
- connect a frontend to a simple backend with guidance;
- understand core AI literacy concepts, including training data, model limitations, bias, hallucination, and responsible AI use;
- use an existing AI API or AI-enabled feature appropriately;
- explain the basic flow of data through a full-stack application;
- identify and fix common programming errors with teacher guidance or a debugging checklist;
- customize a provided project scaffold and add meaningful original features;
- explain what they built, how it works, and how AI was used.

### Mastery Expectation

For most topics:

**Target: Mastery Level 2–3**

Students should be able to:

- explain an example while looking at it;
- rebuild a familiar pattern using a checklist;
- make meaningful modifications to working code.

For selected core skills, students should reach **Level 3 consistently**.

Level 4 or Level 5 work is encouraged for advanced students but is not required across the entire course.

---

## High School Track — Independent Full-Stack AI Development

### Core Goal

**Rebuild · Debug · Integrate · Transfer**

High School students are expected to move beyond guided implementation and develop increasing independence as software developers.

By the end of the course, a High School student should be able to:

- maintain a well-documented GitHub repository with meaningful commits;
- independently create responsive frontend interfaces;
- use JavaScript or TypeScript for application logic, asynchronous operations, and API communication;
- design and organize React components;
- build major parts of a Next.js frontend independently;
- write Python functions and modules for backend logic and data processing;
- design FastAPI endpoints, request/response schemas, validation, and basic error handling;
- independently connect frontend and backend systems;
- integrate an AI API into a working application;
- understand the purpose of retrieval, grounding, vector stores, and RAG-style application architecture;
- complete a practical data and machine-learning workflow using data preparation, train/test separation, a baseline model, evaluation, and reflection;
- debug common frontend, backend, API, and integration problems independently;
- make architectural and implementation decisions and explain those decisions;
- build substantial portions of the final full-stack AI application with limited scaffolding;
- explain system architecture, data flow, limitations, and responsible AI use.

### Mastery Expectation

For most core topics:

**Minimum Target: Mastery Level 3**

For major programming and application-development skills:

**Target: Mastery Level 4**

For the capstone and selected core skills:

**Target: Mastery Level 4–5**

High School students should increasingly be able to rebuild core patterns without notes, debug problems, modify systems, and transfer their knowledge to new situations.

## Same Mission, Different Expectations

The two groups may complete the **same Class Mission**, but the required evidence and level of independence are different.

| Area | Middle School | High School |
|---|---|---|
| Teacher support | High | Gradually reduced |
| Starter code | Frequently provided | Used selectively |
| Checklists | Regularly available | Reduced over time |
| Coding independence | Guided | Increasingly independent |
| Debugging | With support | Mostly independent |
| Modification | At least one meaningful change | Multiple meaningful changes |
| Architecture | Explain basic structure | Explain and make design decisions |
| AI Literacy | Strong emphasis | Strong emphasis + application architecture |
| AI Integration | Modify/use provided integration | Build/integrate independently |
| ML | Conceptual + guided workflow | Practical end-to-end workflow |
| Final Project | Scaffolded full-stack project | Independent full-stack AI project |
| Mastery | Mostly Level 2–3 | Mostly Level 3–4; capstone 4–5 |

---

## Final Project Differentiation

Both tracks work toward the same broad final-project theme, such as the **AI School Assistant**, but the amount of scaffolding is different.

### Middle School Final Project

Students may receive:

- a working project scaffold;
- starter frontend components;
- a provided FastAPI structure;
- a partially completed AI integration.

Students must:

- customize the application;
- add meaningful features;
- connect and test major components;
- document their work;
- explain the basic architecture and data flow.

### High School Final Project

Students receive significantly less scaffolding.

Students must:

- build major frontend and backend components;
- integrate APIs;
- implement or configure the AI component;
- debug integration problems;
- document architecture and design decisions;
- explain how data moves through the system;
- justify important technical choices.

## Implementation Rule for Class Missions

When a mission needs different requirements, use two short sections rather than creating separate mission files:

```text
Middle School Requirement
- Complete the provided scaffold.
- Explain the core pattern.
- Make at least one meaningful modification.
- Submit required evidence.

High School Requirement
- Rebuild the core pattern with reduced scaffolding.
- Make multiple meaningful modifications.
- Debug independently.
- Explain architecture or design choices.
- Submit evidence and reflection.
```

This keeps the course maintainable while preserving clear age-appropriate expectations.

---

## Summary

> **Middle School:** Build, modify, and explain.
>
> **High School:** Rebuild, debug, integrate, and transfer.

The goal is not to give younger students a different technology stack. The goal is to adjust **scaffolding, independence, depth, and mastery expectations** while keeping one coherent course pathway.
