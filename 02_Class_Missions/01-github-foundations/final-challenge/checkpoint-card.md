# GitHub Team Launch — Automatic Checkpoint Card

The repository's **🚀 GitHub Team Launch Progress** Issue is the official checkpoint page. Do not manually mark this file as proof of completion.

## Automatic Progress

The checker evaluates these areas:

- [ ] Three correctly named feature Issues exist
- [ ] Public Project evidence includes all three feature Issues
- [ ] `feature-html`, `feature-css`, and `feature-javascript` have repository evidence
- [ ] Owner, CSS collaborator, and JavaScript collaborator are three distinct accounts working in the same shared repository
- [ ] Feature Issues are assigned to the correct role accounts
- [ ] Every feature PR contains a local-style Git commit
- [ ] Commit messages are meaningful
- [ ] PR titles/descriptions/testing/Issue-closing syntax meet the challenge requirements
- [ ] Each role changes its assigned source file without taking over the other roles' files
- [ ] Owner leaves substantive review evidence on both collaborator PRs
- [ ] At least one collaborator responds to **Changes Requested** with a later commit on the same PR
- [ ] All three PRs are merged and all three feature Issues close
- [ ] All three participants prove their local `main` is synchronized to the current remote SHA
- [ ] Final `main` contains non-placeholder HTML, CSS, and JavaScript interaction
- [ ] GitHub Pages is configured and the live HTML/CSS/JavaScript assets pass checks
- [ ] All three participants submit a valid final reflection

## Student Workflow

```text
Issue
→ Project
→ clone
→ branch
→ edit
→ add
→ commit
→ push
→ Pull Request
→ review
→ respond to feedback
→ merge
→ switch main
→ pull
→ deploy
→ reflection
```

## Rule

Collaborators do **not** merge their own feature PRs. They submit work and respond to review. The Owner / Maintainer controls integration into `main`.

When the Progress Issue reaches all checkpoints, it closes automatically and the challenge is complete.
