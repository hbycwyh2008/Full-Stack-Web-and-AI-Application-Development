# Lesson 2: README and Commit History

**Duration:** 45 minutes  
**Target mastery after lesson:** Level 2–3

---

## 1. Lesson Goal

Students understand **commit history as learning evidence**, improve `README.md`, create `learning-log.md`, and practice **meaningful commit messages**.

## 3. Core Vocabulary

| Term | Definition |
|---|---|
| **Commit message** | Short description of what changed in that snapshot |
| **Commit history** | Ordered list of commits — your learning timeline |
| **Learning log** | Running record of what you did, learned, and struggled with |
| **Meaningful commit** | Message that tells a future reader (or teacher) what changed |

---

## 4. Core Pattern

```text
small change → meaningful commit → visible history
```

## 5. 80-Minute Lesson Flow

Standard 8-block flow (0–20 warm-up through 76–80 exit evidence).

---

## 6. Skill Warm-up (0–20 min)

**Task:** 5–8 min clip on commits OR teacher shows two repos: one with good history, one with single `update` commit.

**Students write:** Which history helps a teacher see learning? Why?

Skim `git-github-command-cheatsheet.md` — good vs bad messages.

---

## 7. Entry Check (20–30 min)

1. What is a commit in your own words?
2. Where on GitHub do you see commit history?
3. Why is `asdf` a bad commit message?
4. What did your Lesson 1 commit change?
5. Write one **good** commit message for “added learning goals to README.”

---

## 8. Talk Robin Round 1 (30–34 min)

- A: “Commit history is learning evidence because…”
- B: “One good commit message I wrote or saw is…”
- Shared: One confusion about commits vs saving.

---

## 9. Teacher Pattern Explanation (34–45 min)

### Commit messages

**Good examples:**

```text
Add learning expectations
Add first learning log
Update README with course goals
Fix typo in project description
```

**Bad examples:**

```text
update
asdf
final
change
```

**Rule:** Describe **what changed**, not your mood.

### Pattern today

1. Open `cs-learning-log`
2. Review **Commits** tab — read past messages
3. Improve `README.md` (add goals, fix formatting, personal detail)
4. Create `learning-log.md` at repo root
5. Add **Lesson 1** and **Lesson 2** reflection sections
6. **Separate commits** for README update and learning log (small changes → multiple commits)

**`learning-log.md` starter:**

```markdown
# Learning Log

## Lesson 1 Reflection
- What I did:
- What I learned:
- What was hard:

## Lesson 2 Reflection
- What I did:
- What I learned:
- What was hard:
```

---

## 10. Guided Practice (45–60 min)

1. Class opens Commits tab — teacher narrates one commit
2. Edit README — commit: `Update README with personal learning goals`
3. Create `learning-log.md` — commit: `Add learning log with Lesson 1 reflection`
4. Add Lesson 2 section — commit: `Add Lesson 2 reflection to learning log`

Show how history grows down the list.

---

## 11. Independent Rebuild (60–72 min)

**Checklist:**

- [ ] README improved from Lesson 1 (visible diff)
- [ ] `learning-log.md` exists with Lesson 1 and Lesson 2 reflections (real sentences)
- [ ] At least **two new commits** with meaningful messages
- [ ] Commits tab shows clear progression
- [ ] Can point to which commit changed which file

---

## 12. Talk Robin Round 2 (72–76 min)

- A: “Small change → meaningful commit means…”
- B: “My best commit message today is ___ because ___.”
- Shared: Exit Evidence ready?

---

## 13. Exit Evidence (76–80 min)

1. `learning-log.md` link or screenshot
2. Screenshot of **Commits** tab (multiple messages visible)
3. One sentence: **Why are good commit messages important?**

---

## 14. Mastery Check

| Level | Indicator |
|---|---|
| 1 | Adds learning-log with teacher steps |
| 2 | Explains own commit while looking at history |
| 3 | Rebuilds log + commits with checklist |
| 4 | Writes good messages without examples on desk |

---

## 15. Common Mistakes

- One commit for entire lesson: `lesson 2 done`
- Empty learning-log sections
- README unchanged since Lesson 1
- Fixing typo with message `fix` instead of `Fix typo in README title`
