# Lesson 15 — Figma-to-Code Implementation Sprint

**Mission:** Complete a responsive static implementation and verify design intent systematically.

## Planning (0–10)

Create GitHub issues for the remaining implementation gaps. Do not use one issue called `finish website`.

## Build Sprint (10–55)

Students implement from their Figma prototype using the existing HTML/CSS system. Work occurs on feature/fix branches with meaningful commits.

## Design QA (55–72)

A reviewer compares Figma and implementation across:

- hierarchy/content;
- spacing/typography;
- components/states;
- accessibility;
- narrow/wide layouts.

Every discrepancy is tagged **bug / intentional adaptation / design change needed**.

## Fix Highest-Impact Gaps (72–84)

Students fix issues affecting task clarity, accessibility, or responsive behavior before cosmetic differences.

## PR + Review (84–90)

Open or update a pull request with screenshots and design-QA evidence.

## Success Evidence

The implementation is faithful to the design's purpose and system while remaining accessible and responsive.
