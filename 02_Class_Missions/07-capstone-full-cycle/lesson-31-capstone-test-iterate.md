# Lesson 31 — Capstone Usability Test, QA, and Iteration

## Mission
Use user and technical evidence to decide what must change before release.

## Core Artifact
Usability findings + QA issue board + revised release candidate.

## Launch Challenge — 0–10
Each team predicts the three places users are most likely to struggle. Predictions are saved so they can later be compared with actual evidence.

## Evidence / Resource Scan — 10–25
Prepare task-based usability test and QA checklist from requirements.

## Team Sensemaking — 25–40
Assign facilitator, observer, technical tester, and evidence recorder roles. Rehearse neutral facilitation.

## Studio Build — 40–65
Run tests and collect behavior, task completion, errors, accessibility problems, and technical defects.

## Critique / Test — 65–80
Compare predictions with evidence. Triage findings by impact; fix the release blockers/high-severity items first and retest.

## Ship Evidence — 80–90
Commit verified fixes and preserve remaining known issues honestly.

## Success Evidence
The final product changes because of test evidence, not only because the team wanted more polish.
