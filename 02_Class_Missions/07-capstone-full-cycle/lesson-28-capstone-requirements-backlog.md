# Lesson 28 — Requirements, Scope, and GitHub Backlog

## Mission
Convert capstone research into a buildable release plan.

## Core Artifact
Problem statement + prioritized requirements + GitHub milestone/issues.

## Launch Challenge — 0–10
Students cut an intentionally oversized feature list down to a minimum useful release and explain what they removed.

## Evidence / Resource Scan — 10–25
Review research synthesis and success criteria. Every proposed requirement must have a reason.

## Team Sensemaking — 25–40
Prioritize using **must / should / could / not now**. Identify the smallest release that lets a user complete the primary task.

## Studio Build — 40–65
Create user stories, acceptance criteria, issue backlog, dependencies, milestone, and ownership. Include research, design, implementation, testing, release, and documentation work — not code issues only.

## Critique / Test — 65–80
Another team reads the backlog and identifies hidden work or vague acceptance criteria.

## Ship Evidence — 80–90
Revise scope and commit the release plan.

## Success Evidence
The backlog represents the entire development process and has a defensible minimum scope.
