# Lesson 1: Course Workflow and First GitHub Repository

**Your repo:** `studentName-Full-Stack-Web-and-AI-Application` (you create it today)

**Classroom learning cycle:**

```text
individual learning
→ Talk Robin / group discussion
→ group answer
→ Entry Points Check
→ teacher explains only what students do not understand
→ mission task
→ exit check
→ submission of evidence
```

**Today’s GitHub workflow:**

```text
create repository
→ write README
→ commit changes
→ find commit history
→ submit evidence
```

---

## Lesson Goal

By the end of this lesson, each student should have:

1. A public GitHub repository named `studentName-Full-Stack-Web-and-AI-Application`
2. A simple `README.md`
3. At least one meaningful commit
4. A visible commit history
5. Submitted evidence of the repository, README, and commit history
6. A simple explanation of repository, README, commit, and commit history

## What to Focus On

While watching, discussing, and working, focus only on:

1. **GitHub purpose** — why this course uses GitHub as learning evidence
2. **Repository** — your project on GitHub at your repo link
3. **README.md** — the homepage text visitors see first
4. **Commit** — the save step with a short message after you edit README
5. **Commit history** — the list of saves on the **Commits** tab
6. **Evidence** — links or screenshots that prove your work exists

Use only the GitHub website. No local Git commands today.

## Mini Skill: What You Need Before the Mission

1. **Course repo vs your repo** — this teacher materials repo is **not** where you submit work. Create **your own** repo named `studentName-Full-Stack-Web-and-AI-Application`.
2. **GitHub account** — sign in before class if possible.
3. **One useful habit** — when you get stuck, name the exact step or button you cannot find.
4. **Repo naming** — replace `studentName` with your own name. Use hyphens and `and`; do not use spaces or `&` in the repo name.

# Full-Stack Web and AI Application

## 90-Minute Class Flow

### 0–12 min: Individual Learning

Work silently and use the concept resource.

**Do this individually:**

1. Open **A brief introduction to Git for beginners**: https://www.youtube.com/watch?v=r8jQ9hVA2qs
2. Watch the video once.
3. Write short answers to the prompts below.

```text
GitHub is useful in this course because...
A repository is...
A README is...
A commit is...
Commit history can show learning because...
One step I think I can do myself is...
One step I may need help with is...
```

**Student output:** Seven short notes.

---

### 12–25 min: Talk Robin / Group Discussion

In your group, each student speaks once before anyone speaks twice.

**Share:**

1. Why GitHub is useful in this course
2. Your definition of repository
3. Your definition of README
4. Your definition of commit
5. The step you may need help with

Listen for differences. Do not ask the teacher yet unless your group cannot continue discussing.

**Student output:** Group list of unclear steps or words.

---

### 25–35 min: Group Answer

As a group, prepare one shared answer:

```text
Repository means...
README means...
Commit means...
Commit history means...
GitHub is useful in this course because...
The GitHub workflow today is...
Our group still needs help with...
```

Be ready to share one answer with the class.

**Student output:** One group answer.

---

### 35–45 min: Entry Points Check

The teacher checks what the class already understands before explaining anything.

**Teacher checks:**

1. Which groups can explain the full workflow?
2. Which students do not have a GitHub account ready?
3. Which groups confuse the course repository with the student repository?
4. Which steps are unclear across multiple groups?
5. Which vocabulary words need a quick explanation?

**Teacher explanation rule:** Explain only the unclear parts. Do not run a full teacher-demo-first GitHub onboarding lesson.

If the class is blocked on a specific GitHub screen, the teacher may model that one blocked step, then students return to the mission.

---

### 45–70 min: Mission Task

Create your first course repository.

Keep **GitHub Docs: Hello World** open while you work. Follow the same required steps:

```text
create a repository → edit README → commit changes
```

**Task:**

1. Create a **public** repository named **`studentName-Full-Stack-Web-and-AI-Application`**
2. Add `README.md` using the starter in Mini Skill
3. Fill in your name and one course goal
4. Click **Commit changes**
5. Use a meaningful commit message, such as `Add initial README with learning goals`
6. Copy your repository link

Use the Hello World guide step by step. Ask for help by naming the exact step where you are stuck.

**Mission output:**

- Working repository link
- `README.md` with title and About me section filled in
- At least one commit saved

---

### 70–80 min: Exit Check

Confirm that GitHub saved your work and that you can explain it.

**Do this individually:**

1. Open your `studentName-Full-Stack-Web-and-AI-Application` repository.
2. Find your `README.md`.
3. Find your commit message.
4. Open the commit history.
5. Answer the prompts below.

```text
My repository link is...
My commit message is...
Commit history shows...
A repository is...
A README is...
A commit is...
```

**Oral check if called:** Explain repository → README → commit → commit history using your own repo as evidence.

---

### 80–90 min: Submission of Evidence

Submit your evidence before leaving class.

Check that each link or screenshot clearly shows your own `studentName-Full-Stack-Web-and-AI-Application` repo.

## Teacher Notes

The main purpose of this lesson is not deep Git knowledge.

The main purpose is that every student successfully creates their first GitHub learning repository and understands this pattern:

```text
create repository → write README → commit changes → find commit history → submit evidence
```

Keep the classroom cycle intact:

```text
individual learning
→ Talk Robin / group discussion
→ group answer
→ Entry Points Check
→ teacher explains only what students do not understand
→ mission task
→ exit check
→ submission of evidence
```

Do not begin with a full teacher demo. Let students read, discuss, and produce group answers first. Use the Entry Points Check to decide what needs explanation.

During the mission, check quickly:

1. Who still needs help signing in?
2. Who confuses the course repository with their own repository?
3. Can students find the `Commit changes` button?
4. Can students find commit history?
5. Can students explain repository, README, and commit in simple words?

Do not re-teach the full video or introduce extra GitHub features.

Do not introduce:

- Git CLI
- branches
- pull requests
- merge conflicts
- GitHub Actions
- mastery levels
- AI use policy
