# Lesson 23 — JavaScript Feature Sprint and Debugging

## Mission
Implement a meaningful feature from an issue and debug it using reproducible evidence rather than random edits.

## Core Artifact
A reviewed feature PR containing HTML/CSS/JavaScript changes and a debugging record.

## Launch Challenge — 0–10
Given a bug report with “it doesn't work,” students rewrite it to include **steps, expected result, actual result, environment, evidence**.

## Evidence / Resource Scan — 10–25
Use DevTools console, breakpoints/logging, DOM inspector, and network/storage panels as relevant. Students map each tool to the type of evidence it can provide.

## Team Sensemaking — 25–40
Teams select one open feature issue and write a precondition → input → processing → output → postcondition plan before coding.

## Studio Build — 40–65
Implement on a feature branch. When a defect appears, record hypothesis, evidence, change, and retest. Avoid replacing large blocks of code without understanding the failure.

## Critique / Test — 65–80
Reviewer tests acceptance criteria plus one edge case and reviews the diff. Author responds and revises.

## Ship Evidence — 80–90
Merge only when the PR explains tests and known limits.

## Success Evidence
Students can narrate a debugging process from symptom to evidence to fix.
