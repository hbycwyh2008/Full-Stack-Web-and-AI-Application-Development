# A4 — Independent Transfer and Release

**Length:** 45 minutes. **Evidence:** Transfer evidence and an evidence-based release decision.

Use the [workbook](student-workbook.md) and [teacher guide](teacher-guide.md).

## 0–5 min — Skill Warm-up

Inspect open bugs and latest tested commit. A deployed app can differ from the local build: predict one check to repeat after deployment.

## 5–9 min — Talk Robin 1

Compare ship / ship with known issues / hold. Explain user impact and workaround for one defect.

## 9–14 min — Entry Check

A core task fails on the main target device but desktop passes. Decide readiness and explain; share responses.

## 14–19 min — Core Pattern

Teacher states assessment conditions and models a release gate: all required tests executed, core task passes, no blocker, meaningful known issues, ownership and deployed verification.

## 19–30 min — Guided Practice

On a fresh branch/copy, complete the teacher’s small unseen change. First write criterion and tests with AI closed; then make and explain a small code change with AI closed if JS prerequisites are met. Run new tests and two regression tests. After the individual check, AI may assist further work with disclosure.

## 30–40 min — Independent Rebuild

Individually defend the change and one failed or boundary test. For unfinished JS foundations, perform the process-only transfer task and mark programming mastery pending. Decide release readiness from the evidence.

## 40–45 min — Talk Robin 2 + Evidence

Submit transfer evidence and release decision. Deploy only a ready build through the approved method; record URL/version and repeat the main task plus one invalid-input check on the deployed version. Otherwise record Hold and next fix. Share learning, uncertainty, and next improvement.
