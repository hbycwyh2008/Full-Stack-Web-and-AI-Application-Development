# Lesson 2: Publish and Connect GitHub


| | |
|:---|:---|
| **Time** | 90 minutes |
| **Evidence** | student repo + phase folder |

> [!TIP]
> Mission card → **45–70 Mission Task** → **70–80 Rebuild/Exit** → submit evidence.

## Lesson Goal

Publish your Notion portfolio as a public website and connect it back to your GitHub repository so your showcase and evidence support each other.

By the end of this lesson, someone should be able to open your Notion portfolio, understand your GitHub learning, and click through to your GitHub evidence.

---

## Why This Lesson Matters

A portfolio is only useful if other people can open it, understand it, and verify your evidence.

Today you will turn your draft Notion page into a public learning showcase.

---

## Class Flow

```text
individual learning → Talk Robin / group discussion → group answer → Entry Points Check → teacher explains only what students do not understand → mission task → exit check → submission of evidence
```

---

## 1. Individual Learning

Open the Notion portfolio tutorial:

[How to Build a FREE Website with Notion (Full Tutorial)](https://www.youtube.com/watch?v=w8NQU9k4afM)

Watch only this part today:

**24:36–41:48**

Focus on:

1. How the creator adds supporting sections after the main portfolio section
2. How FAQ or contact sections help visitors understand the page
3. How Notion publishing works
4. What should be checked before sharing a public page

While watching, write short notes for these questions:

1. Which extra section would make your student portfolio stronger?
2. What information should not be shared publicly?
3. What must you test before submitting a public link?
4. Why should the Notion link also appear in your GitHub `README.md`?

---

## 2. Talk Robin / Group Discussion

In your group, each student answers:

1. “Before I publish, I need to check...”
2. “The public audience for my portfolio is...”
3. “My GitHub README should link to Notion because...”

Each person speaks once before anyone speaks twice.

---

## 3. Group Answer

As a group, write one shared answer:

> A portfolio is ready to publish only when...

Your answer should include at least three checks.

---

## 4. Entry Points Check

The teacher checks:

1. Does your Notion page have the required sections from Lesson 1?
2. Does your GitHub evidence link work?
3. Do you understand what information is safe to publish?
4. Do you know how to update your GitHub `README.md`?

The teacher explains only the parts students do not understand yet.

---

## 5. Mission Task

Finish and publish your Notion portfolio.

### Part A: Improve the Page

Add at least two supporting sections:

1. **FAQ**
   - What is this portfolio?
   - What am I learning?
   - Where can people see my work evidence?

2. **Contact or Next Steps**
   - Use school-safe contact instructions only
   - If you should not share an email publicly, write “Contact through teacher or school platform”

3. **GitHub Learning Reflection**
   - What did GitHub help you understand?
   - What was difficult?
   - What will you improve in AI literacy?

### Part B: Publish the Notion Page

In Notion:

1. Click **Share**.
2. Choose the publish option your Notion version provides.
3. Copy the public URL.
4. Open the public URL in a browser tab.
5. Check that the page can be viewed without editing access.

If your school account blocks public publishing, submit a teacher-viewable link and screenshot instead.

### Part C: Connect Notion Back to GitHub

Open your `[studentName]-Full-Stack-Web-and-AI-Application` GitHub repository.

Update `README.md` with a small portfolio section:

```md
## Portfolio

My public Notion portfolio: [paste your Notion link here]
```

Commit the change with a meaningful message:

```text
Add Notion portfolio link to README
```

---

## 6. Independent Rebuild / Exit Check

Without replaying the tutorial, complete this check:

1. Open your public Notion link.
2. Click your GitHub repo link from Notion.
3. Open your GitHub `README.md`.
4. Click your Notion portfolio link from GitHub.
5. Explain the two-way connection in one sentence.

If either link fails, fix it before submission.

---

## 7. Submission of Evidence

Submit:

1. Public Notion portfolio link, or teacher-viewable link if public publishing is blocked
2. Screenshot of the published Notion homepage
3. Screenshot or link showing GitHub Evidence section in Notion
4. Screenshot or link showing your GitHub `README.md` now links back to Notion
5. One sentence: “Notion shows my best learning story; GitHub proves my work because...”

---

## Success Criteria

You are successful if:

1. Your Notion portfolio link opens correctly.
2. Your portfolio includes required sections from Lesson 1 plus at least two supporting sections.
3. Your Notion page links to your GitHub repository.
4. Your GitHub `README.md` links back to your Notion portfolio.
5. Your GitHub commit history shows a meaningful README update commit.
6. You can explain why this course uses both Notion and GitHub.

---

## Common Problems

| Problem | Try first |
|---|---|
| My public link does not open | Check Notion sharing or publishing settings. |
| The link opens editing mode | Copy the public view link, not your private workspace URL. |
| I cannot publish because of school settings | Submit a teacher-viewable link and screenshot. |
| My GitHub README link is broken | Paste the full Notion URL and test it after committing. |
| I only submitted Notion | Also update GitHub; the two-way connection is required. |

---

## Fast Track Option

If most students complete this lesson in about 45 minutes, use the rest of the 90-minute block as a portfolio evidence audit.

Students should check that they have:

1. A working Notion portfolio link.
2. A working GitHub repo link inside Notion.
3. A working Notion link inside GitHub `README.md`.
4. At least one GitHub learning reflection written in their own words.
5. No private personal information published accidentally.

If students are missing evidence, they should fix the evidence before moving into AI literacy.
