# Lesson 30 — Capstone Implementation Sprint

## Mission
Build the minimum useful release through GitHub-managed feature work.

## Core Artifact
Integrated HTML/CSS/JavaScript release candidate with reviewed PRs.

## Launch Challenge — 0–10
Teams inspect backlog status and identify the current critical path. Do not simply divide work evenly if dependencies make that inefficient.

## Evidence / Resource Scan — 10–25
Review design handoff, acceptance criteria, existing branches, and open issues.

## Team Sensemaking — 25–40
Select sprint scope and define how work will integrate. Identify shared files/components that need coordination.

## Studio Build — 40–65
Implement on branches with coherent commits. Use issues, PRs, review, and testing continuously; do not wait until the end to combine everyone's code.

## Critique / Test — 65–80
Run integration review against acceptance criteria and the Figma baseline. Log defects immediately.

## Ship Evidence — 80–90
Merge verified work and update milestone status with evidence.

## Success Evidence
The team can show how code changes map to requirements, design, issues, reviews, and tests.
