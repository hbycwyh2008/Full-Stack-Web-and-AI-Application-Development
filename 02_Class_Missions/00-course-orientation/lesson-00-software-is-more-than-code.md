# Lesson 00 — Software Is More Than Code

## Mission
Build a shared model of how a software product moves from a human problem to a released and improved product.

## Core Artifact
`docs/software-lifecycle-map.md`

## Launch Challenge — 0–10
Individually sort these cards into an order that could produce a useful product: **user problem, research, requirements, design, implementation, testing, release, feedback, maintenance**. Add arrows when a step may repeat.

## Evidence / Resource Scan — 10–25
Inspect two familiar digital products. For each, record visible evidence of at least four lifecycle stages. Students are looking for evidence, not guessing the hidden code.

## Team Sensemaking — 25–40
Teams compare lifecycle maps. Each student must defend one arrow. Record one disagreement about whether software development is linear or iterative, then agree on a team model.

## Studio Build — 40–65
Create a lifecycle map with these required ideas:

`discover -> define -> design -> build -> test -> release -> learn -> iterate`

Add the role of **GitHub**, **HCI research**, **Figma**, **HTML/CSS/JavaScript**, and **AI literacy** to the relevant stages.

## Critique / Test — 65–80
Swap maps. The reviewing team gives one scenario: “users fail to complete the main task after release.” The original team must show where the lifecycle loops back and what evidence would be collected.

## Ship Evidence — 80–90
Revise the map and commit it. Commit message must describe the conceptual change, not just say “update file.”

## Success Evidence
A student can explain why coding is one stage inside a larger iterative development process.
