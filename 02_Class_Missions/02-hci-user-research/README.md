## Unit flow

~~~text
Needfinding
→ collect evidence
→ bias check
→ survey / sample check
→ synthesize evidence
→ define user needs
→ Brainstorm / Design Alternatives
→ hand off to Figma prototyping
~~~

The boundary is intentional:

> **HCI unit ends with Brainstorming. Figma begins with Prototyping.**

## End-of-unit mastery check

After **L08**, use the **HCI Needfinding + Brainstorming Unit Test**.

It checks whether students can independently:

- frame a user-research problem;
- identify and reduce bias;
- separate evidence from interpretation;
- evaluate survey questions;
- reason about samples and claim strength;
- derive a user need from evidence;
- generate structurally different alternatives;
- avoid fixation and choose a direction worth prototyping.

The test is the final HCI checkpoint before students enter Figma prototyping.

## Student mental model

### Needfinding

Ask:

1. What do we actually know?
2. What are we assuming?
3. What do we still need to learn?
4. Which method can answer that?
5. What bias could distort the evidence?

### Brainstorming

Ask:

1. What evidence-backed need are we solving?
2. Have we generated enough ideas before judging?
3. Are the alternatives structurally different?
4. Are we stuck on the first idea?
5. Which direction is most worth prototyping?

## HCI → Figma handoff

Students enter the Figma unit with:

- one evidence-backed user need;
- multiple brainstormed ideas;
- three structurally different alternatives;
- one selected direction;
- one primary user flow;
- one uncertainty worth testing.

They do **not** need a polished interface yet.

The next unit begins with:

> **Prototype → Evaluate → Iterate**
