# Phase 3: Cursor Quick Win

## Phase Goal
Get a fast, visible AI-assisted result to build confidence with Cursor.

## Key Concepts
- What Cursor is and how AI-assisted coding works.
- Reading and lightly modifying AI-generated code.
- The difference between accepting code and understanding code.

## Required Student Output
- A small AI-assisted web page or mini app.
- At least one manual change you made to the generated code.
- A short AI usage reflection.

---

## Lesson Sequence

This phase runs over about two lessons (one week standard pace).

| Lesson | Focus |
|---|---|
| 3.1 | Set up Cursor + first AI-assisted build |
| 3.2 | Modify, understand, and reflect |

---

## Lesson 3.1 — First AI-Assisted Build

**Lesson Goals:** Install Cursor and generate a working mini page.

- **Warm-up (5 min):** "What would you build if coding were fast and easy?"
- **Mini Lesson (15 min):** Tour Cursor; show how to write a clear prompt and read the result. (Optional: Resource #9.)
- **Guided Practice (20 min):** Whole class builds the same small page with Cursor (e.g., a profile card or simple counter).
- **Independent Work (10 min):** Each student customizes the page (colors, text, one feature).
- **Exit Ticket:** What did Cursor generate, and what did you change?
- **Homework:** Finish the mini app so it runs.

---

## Lesson 3.2 — Understand and Reflect

**Lesson Goals:** Prove understanding of the generated code and reflect on AI use.

- **Warm-up (5 min):** "Explain this line" — show a line of generated code and ask what it does.
- **Mini Lesson (10 min):** Why "I accepted it" is not the same as "I understand it." Connect to Phase 0.
- **Guided Practice (20 min):** Students annotate their code with comments explaining 3 lines in their own words.
- **Independent Work (15 min):** Write an AI usage reflection using `01_Student_Templates/AI_Usage_Reflection_Template.md`.
- **Exit Ticket:** Name one thing you accepted from AI that you did NOT fully understand.
- **Homework:** Push the mini app to GitHub with a short README.

---

## Submission Requirements
- [ ] Working mini app.
- [ ] One documented manual change.
- [ ] Code annotated with student explanations.
- [ ] AI usage reflection completed.

## Common Student Problems
- Accepting code blindly without reading it → require the "explain 3 lines" annotation.
- Over-ambitious projects that break → keep the first build small.
- Not testing before submitting → require the app to actually run.

## Teacher Notes
> 重点是建立信心，同时坚持"必须理解代码"的规则。The focus is confidence, but hold the Phase 0 rule: students must read, test, and understand what they submit. Resource #9 is a good optional intro; remind students our main backend is FastAPI, not Next.js Server Actions.

## AI Lens Reflection
Ask students: *"This is your first time letting AI write code for you. What rule will you set for yourself about checking AI's work?"* Save the answer in Learning Notes.
