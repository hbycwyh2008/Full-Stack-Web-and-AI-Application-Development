# Figma Skills — Quiz + Independent Practical

**Total:** 100 points = knowledge 20 + practical 80.
**Purpose:** Check tool skills separately from the [30-point Design Cycle Test](Figma_Design_Cycle_Unit_Test.md).
**Delivery:** Stage checkpoints across several meetings; a final transfer task uses new labels/content. Do not attempt the entire assessment in one 45-minute lesson.
**Conditions:** Individual work; no AI, copied completed file, or step-by-step tutorial during assessment. The teacher supplies only the brief and assets. Follow school accessibility accommodations. Practice before assessment may use the assigned resources.

## A. Knowledge Quiz — 20 Points

Use short written answers, diagrams, or a brief individual oral explanation. Each item is worth 2 points: 1 for the correct concept and 1 for an explanation/example. Administer the relevant items after teaching the skill.

| Item | Question | Skill |
|---|---|---|
| Q1 | When would you use a Frame rather than a Group? Give a useful example. | Structure |
| Q2 | A text layer appears on the wrong screen when duplicated. What would you inspect in the layer hierarchy? | Layers |
| Q3 | How would you keep several headings visually consistent and update them efficiently? | Styles |
| Q4 | Explain the difference between padding and gap using a button or card. | Auto Layout |
| Q5 | A button should grow with its label, while a card should use available parent width. Explain where Hug and Fill are useful and how Fixed differs. | Sizing |
| Q6 | What is the relationship between a main component and an instance? | Components |
| Q7 | Several cards need different text but the same layout. What should be shared, and what can differ? | Overrides |
| Q8 | When are variants useful? Give two states of the same UI element. | States |
| Q9 | What must be configured for clicking a button to navigate to another frame? | Prototype |
| Q10 | How will you check that a classmate can open your prototype and return from a dialog? | Sharing/interaction |

## B. Practical Tasks — 80 Points

Use a small **classroom activity signup** prototype as the assessment brief. This is a practice scenario, not a description of Skill Board's features. The teacher supplies two activity names, a short and long title, image assets, and target widths.

| Skill | Task and observable checks | Points |
|---|---|---:|
| Structure and editing | Two named screen frames (2); correct layer nesting (3); editable text/shapes (2); sensible layer names (3) | 10 |
| Visual consistency | Readable text hierarchy (5); consistent alignment/spacing (5); reusable color/text styles plus correctly fitted image (5) | 15 |
| Auto Layout | Appropriate padding/gaps (5); label change does not break button (5); card layout responds to supplied width without overlap using sensible sizing (5) | 15 |
| Components | Main component and at least two genuine instances (5); main update propagates (5); instance content differs without breaking shared layout (5) | 15 |
| Variants | At least two meaningful variants, e.g. default/disabled (5); student selects the appropriate state and explains its purpose (5) | 10 |
| Prototype and sharing | Correct start/flow and navigation to success (5); overlay opens and closes/returns without a dead end (5); accessible prototype link checked from a peer's account (5) | 15 |
| **Practical total** | | **80** |

### Live Transfer Check

The teacher chooses a change after the first submission:

- replace a short label with a longer one;
- change the frame width;
- update the shared button/card style;
- select another component state;
- repair a broken navigation connection.

The student performs the change and explains it. Score the corresponding rubric row from this observed performance; do not add hidden bonus marks. A Figma disabled-state appearance alone does not implement production form validation.
