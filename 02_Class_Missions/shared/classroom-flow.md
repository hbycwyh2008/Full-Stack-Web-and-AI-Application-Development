# Classroom Flow — Canonical 90-Minute Structure

This file is the **required classroom structure** for the canonical lessons in this course. It matches the **Our Classroom Flow** poster.

The flow is fixed, but the activity inside each block should vary with the lesson. The class should **not** become teacher question → student answer → teacher question.

## The Seven Blocks

| Time | Block | Student role | Teacher role |
|---|---|---|---|
| **0–10 min** | **Entry Point Check** | Work individually on a short task that exposes prior ideas, misconceptions, or strategy | Observe; do not front-load the answer |
| **10–25 min** | **Individual Learning** | Use **one required resource/evidence source** and record focused evidence | Make the resource and focus criteria clear |
| **25–40 min** | **Talk Round 1** | Compare evidence, explain reasoning, disagree, and revise ideas with peers | Listen for patterns; avoid controlling the discussion |
| **40–55 min** | **Entry Points Check / Teacher Diagnosis** | Produce a group claim, model, classification, trace, or unresolved point | Diagnose common barriers; give only a short targeted clarification when needed |
| **55–75 min** | **Guided Practice / Mission Task** | Build, design, code, investigate, test, or make a decision using the lesson evidence | Coach and intervene only where the work reveals a need |
| **75–85 min** | **Exit Check** | Complete an individual transfer, explanation, test, or reflection | Check whether understanding transfers beyond the group task |
| **85–90 min** | **Submission** | Submit durable learning evidence | Verify required evidence is present |

## What Can Change Inside the Flow

The **seven blocks do not change**, but the activity format can.

Examples:

- card sort / classification;
- reverse engineering;
- product teardown;
- code tracing;
- predict → run → explain → modify;
- debugging lab;
- interview / observation;
- affinity mapping;
- design studio;
- Figma critique;
- PR review simulation;
- jigsaw reading;
- usability test;
- development sprint.

The goal is to preserve the learning cycle without making every lesson feel identical.

## One Required Resource Rule

During **Individual Learning**, each mission identifies one main resource or evidence source. Students should not spend the block browsing a playlist or choosing among many unrelated resources.

The required resource may be:

- one short video;
- one document excerpt;
- a live website/product;
- a code sample;
- a Figma artifact;
- user-research evidence;
- a selected reading section;
- a test log or Git history.

Optional support may be provided only when students are stuck.

## Teacher Diagnosis Is Not a Lecture Block

The 40–55 minute block exists so the teacher can respond to evidence from students' work.

A good pattern is:

1. groups display one claim/model/decision and one unresolved point;
2. groups compare each other's evidence;
3. teacher identifies a shared misconception or bottleneck;
4. teacher gives a **brief micro-lesson** only if the class evidence shows it is needed;
5. students immediately apply the clarification.

Do not pre-plan fifteen minutes of teacher questioning when students can discover the idea through evidence and discussion.

## Evidence Rule

Every class ends with durable evidence. Depending on the lesson, this may be:

- GitHub commit / issue / PR;
- research notes;
- affinity map;
- requirements document;
- Figma frame/prototype;
- HTML/CSS/JavaScript artifact;
- debug/test log;
- usability findings;
- release note;
- individual reflection.

Working output alone is not sufficient. Students should be able to explain, rebuild, debug, modify, test, or transfer the relevant idea.
