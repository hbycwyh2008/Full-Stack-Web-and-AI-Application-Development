# 当前教学安排：Figma、产品评估、网页游戏与基础 AI 素养

更新：2026-10-19。适用：Full Stack 普通班、编程与英文阅读基础较弱的学生。

这是本次课程调整的入口。保留原有课程目标、00–32课号、GitHub 工作流和45分钟课堂结构；课号表示教学主题，不表示只能用一次课完成。Figma 技能训练、测评、Skill Board 测试和游戏制作可以增加练习课。

## 1. 学习顺序

| 阶段 | 学习内容 | 必须留下的证据 |
|---|---|---|
| 已有 HCI 基础 | Needfinding → 表达需求 → individual/group brainstorming → design alternatives → prototyping | 需求证据、不同方案、选定的核心任务 |
| Figma | 基础工具 → 可点击线框图 → 布局与样式 → Auto Layout → Components/基础 Variants | 原型链接、图层与组件结构、技能操作证据 |
| Figma 技能检查 | 分技能短 Quiz＋独立操作测试 | 知识20分＋操作80分的技能记录 |
| 两种评估方法 | Heuristic Evaluation＋Usability Testing | 原则检查表、无引导任务、观察记录 |
| 共同案例 | 评估 Morgan 的 Skill Board，再迁移到自己的原型 | 问题位置、观察证据、影响、修改建议 |
| HTML → CSS | 搭页面结构，再还原自己的 Figma 设计 | 语义化、可访问、响应式页面 |
| JavaScript 网页游戏 | 港科大课程打基础＋Canvas项目课应用 | 可运行游戏、代码解释、独立改造、测试与 GitHub 历史 |
| 回到自己的项目 | 将事件、状态、反馈等知识用于设计项目 | 核心交互、测试记录、修复与复测 |

低保真原型一旦能验证核心任务，就可以测试；不用等所有视觉功能学完。Skill Board 是共同评估练习，不能代替学生自己项目的测试与迭代。

## 3. 两种评估＋Skill Board

- Heuristic Evaluation：按明确的可用性原则检查界面，先独立记录，再汇总。
- Usability Testing：目标用户实际完成任务，主持人观察，不告诉对方点击路径。
- [共同案例任务与记录模板](../02_Class_Missions/03-figma-product-design/skill-board-evaluation-lab.md)

原课程 Core 3（Affordance/signifier、Mapping、Constraints）继续使用。Nielsen 原则中的状态可见性、一致性与标准、用户控制与自由作为本次启发式检查的补充，不把两套名称混成同一套原则。

对于同一批第一次使用 Skill Board 的参与者，先测试再做原则检查；提前检查过界面的同学可以主持或观察，由尚未接触界面的人参加首次使用测试。不要为了顺序要求耽误修复学生自己原型的明显故障。

## 4. 网页游戏：两门 Coursera 课程配合

1. [香港科技大学：Learning HTML, CSS and JavaScript through Game Development](https://www.coursera.org/learn/learning-html-css-and-javascript-through-game-development)：基础主线，优先 M1、M2和M5的变量／数组／对象／函数。
2. [EDUCBA：Apply HTML5 Game Development Concepts with Canvas](https://www.coursera.org/learn/apply-html5-game-development-concepts-with-canvas)：应用项目，选 Canvas 基础、Ping Pong、Collect the Square；位掩码优化后置。

[模块、前置知识、课号和独立改造任务](../02_Class_Missions/05-javascript-interaction/coursera-web-games-path.md)

采用“基础概念 → 跟做一小段 → 解释／追踪 → 关闭教程独立修改 → 测试”。港科大含 jQuery，后续游戏可能依赖它；不把跳过 jQuery 后的相关作业标成可直接完成。基础班优先原生 JavaScript，不要求两门课整套刷完。

课程目录核对日期：2026-10-19。平台学习时长包含练习，不等于视频时长或本校课堂课时。

## 5. 基础班 AI 素养

核心读物仍是 Melanie Mitchell 的 *Artificial Intelligence: A Guide for Thinking Humans*。以教师精选、课堂内阅读为主，不照搬 ASC 的完整深度阅读安排，不要求学生在家读完整章。

| 主题 | 必须掌握 | 简短证据 |
|---|---|---|
| AI是什么 | 固定规则、从数据学习，以及AI不只有一种方法 | 解释一个对比例子 |
| AI怎样学习 | 数据／例子 → 学习规律 → 对新输入预测；训练与使用不同 | 画并解释输入输出图 |
| AI的任务 | 分类、数值预测、内容生成 | 给例子分类并说明输入输出 |
| AI为什么出错 | 数据、偏差、新情境；表现好不能直接证明理解 | 分析一个失败案例 |
| 有效使用生成式AI | 目标、背景、要求、迭代与验证 | 保存提问、结果、核查与修改 |
| 负责任使用 | 隐私、披露、偏差、对最终作品负责 | 完成情境判断与AI使用说明 |

- [六主题基础路径：课堂活动、阅读选择、过关要求](../02_Class_Missions/06-ai-literacy/foundation-path.md)
- [基础路径检查表](../04_Assessment/AI_Literacy_Checklist.md)

默认放在21–24编号单元中连贯完成，六个主题先按六次45分钟课规划，按表现补练。涉及AI辅助编程前，先落实隐私、披露与核查规则。责任习惯贯穿开发，阅读不必强行联系网页项目；教师可以另外选择并行安排，但这不是自动生效的“每节前15分钟”要求。

暂缓神经网络内部结构、反向传播、CNN/RNN、强化学习算法、AlphaGo技术细节、复杂抽象与类比；AI历史只作简短背景。原十二次阅读路径保留为拓展，不能与基础路径累计成全班必修。

## 6. 课堂节奏与交付

每次45分钟沿用：Skill Warm-up → Talk Robin 1 → Entry Check → Core Pattern → Guided Practice → Independent Rebuild → Talk Robin 2 + Evidence。

学生先体验、观察或阅读，分享一个例子和发现，再独立完成迁移任务。默认无固定课前阅读作业；未完成的证据按课程既有短时补交规则处理。

本次安排不要求新框架、完整设计系统、AI模型训练或强制AI功能。完成核心任务、解释自己的操作／代码、用证据修正作品，是过关依据。
