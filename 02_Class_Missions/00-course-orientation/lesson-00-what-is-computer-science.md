# Lesson 00 — Computer Science and Computational Thinking

**Prerequisite:** [Required Orientation — Learn the Course Through the Four Posters](required-orientation-four-posters.md)

**Length:** 45 minutes

**Classroom Flow:** [Canonical 45-Minute Structure](../shared/classroom-flow.md)

**Mission:** Define computer science and apply computational thinking to solve a non-code problem.

**Required Resource:** [Student workbook and warm-up learning brief](lesson-00-student-workbook-template.md)

**Durable Evidence:** `reflections/lesson-00-what-is-computer-science.md`

## Two Required Learning Outcomes

By the end of this lesson, students can:

1. **Define computer science** as the study of computation and information,
   while explaining that programming is an important tool but not the whole
   discipline.
2. **Use computational thinking to solve a problem** through decomposition,
   pattern recognition, abstraction, algorithm design, and test/refine.

## 0–5 min — Skill Warm-up

Students use the **Warm-up Learning Brief** in the workbook:

1. watch the teacher-selected excerpt from
   [Khan Academy — What is computer science?](https://www.khanacademy.org/computing/in-class-11-computer-science/xab724c3e878917b8%3Acomputer-system/xab724c3e878917b8%3Asoftware/v/what-is-computer-science);
2. read the short computational-thinking card;
3. record one idea learned and one unclear point.

Prepared question:

> How can someone use computer-science thinking before writing any code?

---

## 5–9 min — Talk Robin 1

Partners take turns sharing:

- their current definition of computer science;
- one idea about problem solving from the learning brief;
- one point that remains confusing;
- their answer to the prepared question.

The listener paraphrases before switching:

> “I heard you say ...”

Each student records one useful partner idea.

---

## 9–14 min — Entry Check

Pairs share their strongest answer or question with the class. Record claims
under:

| We think we understand | We are unsure about |
|---|---|
|  |  |

Use these checks if students need prompts:

1. Is computer science the same as programming? Why or why not?
2. What makes a problem suitable for computational thinking?
3. Must computational thinking always use a computer?
4. What is the difference between a problem and an algorithm?

Listen for misconceptions, but save the correction for Core Pattern.

---

## 14–19 min — Core Pattern

Correct misunderstandings from the class share. Teach both required patterns.

### Core 1 — Definition of Computer Science

```text
computer science studies computation and information
→ programming expresses and builds computational solutions
→ programming is important, but it is not all of computer science
```

Students must know:

- a **program** is a set of instructions a computer can execute;
- **programming** is the practice of designing and expressing those
  instructions;
- **computer science** studies computation and information, including
  algorithms, data, systems, networks, cybersecurity, HCI, software
  engineering, AI, programming languages, and computing's effects on society.

### Core 2 — Computational Thinking for Problem Solving

```text
define the problem and goal
→ decompose it into manageable parts
→ recognize useful patterns
→ abstract: keep relevant details and ignore distractions
→ design an algorithm: clear ordered steps or rules
→ test with cases, find failures, and refine
```

The moves support one another and may repeat. Computational thinking can be
used before coding and can also improve non-code processes.

---

## 19–30 min — Guided Practice

### Shared problem

> At the beginning of class, distributing 15 shared laptops to 30 students
> takes too long. Devices, chargers, and users are sometimes mismatched. Design
> a fair process that distributes the laptops in under three minutes and keeps
> an accurate record without collecting unnecessary personal information.

Complete the Computational Thinking Canvas with teacher support:

1. **Define:** state the exact goal, users, constraints, and success criteria.
2. **Decompose:** break the process into smaller parts.
3. **Patterns:** identify repeated actions, bottlenecks, or common failures.
4. **Abstract:** decide which information matters and which details do not.
5. **Algorithm:** write clear ordered steps for distribution and return.
6. **Test and refine:** test an absent student, a missing charger, and a broken
   laptop; revise the steps where they fail.

Teacher models the first part, then pauses after abstraction for a class check.
Students finish the algorithm and testing with support.

---

## 30–40 min — Independent Rebuild

Students close the group answer and choose one new problem:

- **A:** Students cannot quickly find an item in the school lost-and-found.
- **B:** A project team keeps editing different file versions and cannot tell
  which one is current.
- **C:** Returning library books creates a long queue just before class.

Independently apply the complete Computational Thinking Canvas:

1. define the problem, goal, constraints, and success criteria;
2. decompose it into at least three parts;
3. identify one useful pattern;
4. name the relevant information and one distracting detail to ignore;
5. design an ordered algorithm;
6. test one normal case and one edge case;
7. refine one step after testing.

No code is required. The evidence is the student's reasoning and revised
problem-solving process.

---

## 40–45 min — Talk Robin 2 + Evidence

Partners briefly explain:

1. their definition of computer science;
2. how one computational-thinking move improved their solution;
3. what changed after testing.

Each student records:

- **What I learned about computer science**
- **What I learned about computational thinking**
- **What is still confusing / what I still want to ask**
- **One thing I could do better next time**
- **One piece of evidence that proves my learning**

## Success Evidence

Students can:

- define computer science and distinguish it from programming;
- explain decomposition, pattern recognition, abstraction, and algorithms;
- apply all computational-thinking moves to a new non-code problem;
- use test results to refine a proposed solution;
- record a learning gain, remaining question, and next improvement.

## Assessment Stance

Assess definition accuracy, connected reasoning, testing, revision, and
transfer. Do not grade memorization of one sentence or reward a list of
computational-thinking terms without a coherent solution.
