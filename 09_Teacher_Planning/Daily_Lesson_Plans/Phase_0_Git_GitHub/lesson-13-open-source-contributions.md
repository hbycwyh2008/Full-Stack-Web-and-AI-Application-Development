## Lesson Goal

After watching the official video, students can distinguish a fork from a branch and evaluate whether a repository is ready for beginner contributions.

This lesson uses **one video and one guided practice**. Do not re-teach the Classroom Flow posters and do not assign another playlist video as homework.

### 0–10 min: Skill Warm-up

Watch **playlist #14 only**: [Getting started with open source contributions for beginners](https://www.youtube.com/watch?v=WldXhauP024).

While watching, record:

- One new term
- One action demonstrated
- One question to test during practice

### 10–13 min: Talk Robin 1

- **A:** “The video's main idea is…”
- **B:** “A step I need to remember is…”

### 13–17 min: Entry Check

1. What artifact did you create last lesson?
2. Where can you verify a change in GitHub?
3. What must never be copied into a public repository?

### 17–21 min: Core Pattern

Teacher demonstrates the task once and points out where students can verify the result. Students identify the action, the artifact, and the evidence before beginning.

### 21–32 min: Guided Practice

1. Choose a teacher-approved open source practice repository and inspect its README, license, contribution guide, and beginner issues.
2. Without replaying the video, fork it, create a clearly named branch in the fork, and make one harmless documentation change.
3. Commit the change in the fork and open the compare view back to the original repository.
4. Do **not** submit the upstream pull request unless the teacher and project rules approve it. Record the repository, rule followed, branch, and proposed change in `github-foundations/13-open-source-contribution-plan.md`, then commit the plan.

### 32–40 min: Independent Rebuild

Using a second teacher-approved repository, independently locate the license and contribution rules, distinguish fork from branch, and identify one suitable beginner task. Do not submit an unsolicited pull request.

### 40–45 min: Talk Robin 2 + Evidence

Explain when to use a branch, when to use a fork, and why contribution rules come first.

Add to `learning-log.md`:

```markdown
## Lesson 13
- What I did:
- What I learned:
- What was hard:
- Evidence link:
```

Commit the learning-log update if the lesson's practice did not already require that exact commit. **Homework is only the unfinished Lesson 13 learning-log entry; no video homework.**

## Common Mistakes

- Watching or assigning a second playlist video
- Completing clicks without checking the resulting artifact
- Using vague commit messages such as `update`
- Publishing passwords, tokens, recovery codes, or other private information
- Treating a screenshot as a substitute for repository evidence
