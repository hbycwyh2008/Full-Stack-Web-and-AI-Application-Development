# Lesson 0: What Is GitHub? — Understanding the GitHub Workflow

**Phase:** 0 — Git & GitHub  
**Duration:** 45 minutes  
**Flow:** Concept → Analogy → Guided GitHub Practice → Evidence  
**Student repo:** `YourName-Full-Stack-Web-and-AI-Application-Development`

---

## Lesson Goal

By the end of this lesson, students can:

- explain in their own words what GitHub is;
- describe the basic GitHub collaboration workflow;
- explain **commit as a snapshot**;
- connect repository, branch, commit, pull request, review, and merge to a collaboration process they already understand;
- complete a first guided GitHub workflow using GitHub's Hello World tutorial and Introduction to GitHub Skills exercise.

This lesson builds a mental model of the workflow before later lessons isolate individual Git and GitHub skills.

---

## Warm-up — What Is GitHub?

Watch: **[What is GitHub?](https://www.youtube.com/watch?v=4lkrx2U9f6I)**

While watching, pay attention to:

- What GitHub is used for
- How people collaborate on GitHub
- What happens when someone wants to make a change
- Terms such as **repository, branch, commit, pull request, review,** and **merge**

You do not need to understand every term yet. The goal is to get a first picture of how GitHub supports collaboration.

---

## Core Workflow

```text
Repository
→ Branch
→ Make changes
→ Commit (snapshot)
→ Pull Request
→ Review / Discussion
→ Merge
```

### Core Vocabulary

| Term | Working meaning for this lesson |
|---|---|
| **GitHub** | A platform where people store projects, track changes, and collaborate |
| **Repository** | The shared project and its history |
| **Branch** | A separate line of work where changes can be made without immediately changing the main version |
| **Commit** | A saved **snapshot** of changes at a particular point |
| **Pull Request** | A request to review and discuss proposed changes before combining them with the main work |
| **Review** | Checking, discussing, and improving proposed changes |
| **Merge** | Combining approved changes into the main version |

> **Key idea:** A commit is not simply “saving a file.” A commit records a meaningful snapshot in the project's history.

## Activity 1 — Map Our “What Is CS?” Poster to GitHub

Use the class's earlier **“What Is CS?” poster activity** as a concrete model for the GitHub workflow.

Imagine that the class has one official poster. Students should not all directly change the official version at the same time.

| GitHub concept | Poster analogy |
|---|---|
| **Repository / main** | The official shared poster |
| **Branch** | A copy of the poster used to develop a proposed change |
| **Make changes** | Add, revise, or reorganize ideas on the copy |
| **Commit** | Take a **snapshot** of the copy at a meaningful stage |
| **Pull Request** | Ask the group to consider adding the proposed version/changes to the official poster |
| **Review / Discussion** | Classmates inspect the changes, discuss them, and suggest improvements |
| **Merge** | Approved changes become part of the official poster |

### Check for Understanding

With a partner, explain:

1. Why is a branch like working on a separate copy rather than directly changing the official poster?
2. Why is a commit better described as a **snapshot** than simply “save”?
3. What is the purpose of a pull request?
4. Why does review happen before merge?

---

## Activity 2 — GitHub Hello World

Read and follow GitHub's official **[Hello World](https://docs.github.com/en/get-started/start-your-journey/hello-world)** tutorial.

Create your own Hello World repository and follow the workflow in the documentation.

As you work, identify each of these moments:

```text
Create repository
→ Create branch
→ Make a change
→ Commit the change
→ Open a pull request
→ Review the change
→ Merge the pull request
```

Do not treat the tutorial as a sequence of clicks. At each step, connect the GitHub action back to the workflow and the poster analogy.

---

## Activity 3 — Introduction to GitHub Interactive Exercise

Complete GitHub Skills: **[Introduction to GitHub](https://github.com/skills/introduction-to-github)**.

While completing the exercise, identify where you:

- create or use a branch;
- commit a change;
- open a pull request;
- merge a pull request.

The purpose is to experience the workflow after first understanding its structure.

## Teacher Notes

This lesson should come **before the existing skill-by-skill Git/GitHub sequence**. Its purpose is conceptual orientation: students first see the whole collaboration workflow, connect it to a familiar classroom activity, and then experience it on GitHub. Later GitHub Foundations lessons can isolate individual tools and skills without losing the larger mental model.
