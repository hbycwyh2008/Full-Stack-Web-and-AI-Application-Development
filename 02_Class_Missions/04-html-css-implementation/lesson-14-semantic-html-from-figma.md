# Lesson 14 — Semantic HTML from a Figma Design

## Mission
Translate a designed page into meaningful document structure before styling it.

## Core Artifact
`index.html` implementing one designed screen.

## Launch Challenge — 0–10
Given a screenshot, students individually sketch the document outline and label likely elements such as `header`, `nav`, `main`, `section`, `article`, `form`, and `footer`.

## Evidence / Resource Scan — 10–25
Inspect a semantic and a `div`-heavy version of the same page. Compare readability, accessibility meaning, and maintainability.

## Team Sensemaking — 25–40
Teams defend element choices using content meaning rather than appearance.

## Studio Build — 40–65
Implement the page structure from the Figma baseline. Include headings in logical order, meaningful link/button choices, image alternatives where needed, form labels where applicable, and no styling beyond what is needed to inspect structure.

## Critique / Test — 65–80
Partner reviews the DOM outline and attempts keyboard/navigation reading order. Mark structural mismatches with the intended user flow.

## Ship Evidence — 80–90
Fix structure, commit, and link the commit to the implementation issue.

## Success Evidence
The HTML communicates the page's meaning even before CSS is applied.
